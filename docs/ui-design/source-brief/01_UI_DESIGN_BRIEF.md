# UI重新设计说明｜v0.5.1基础，设计批次UI-01

## 1. 这是什么游戏

竖屏三国动作小游戏，Cocos Creator 3.8.8 / TypeScript / 2D，目标为微信小游戏并保留浏览器版本。玩家控制原创主将左右移动，自动近战、释放武器波，后排弓兵齐射。通过数字门增兵，击败精锐升阶，三阶首次命中Boss触发六秒自动觉醒。

当前三个战斗为乱军突围、夺粮立营、白石解围；关间已经有整军、建营、驻防；当前有长枪、长刀与一个随军队友位置。邢道荣、陈应、赵云按既有解锁进入队伍。屏幕上包括主将/队友/弓兵，真实人数与可见人数不相同，HUD必须显示真实兵力。BGM关闭，保留音效。

用户当前需求仅是UI重新设计与手机避让。角色方向、战斗与存档继续保留。不能将这轮变成重做人物、战争地图、完整三国故事或经营系统。

## 2. 依据与诊断

用户截图为当前手机反馈，优先级高于“360/390宽检查通过”的历史报告。原图各941×2048，只能确认图像像素，不能据此断言手机型号、DPR、逻辑窗口尺寸或真机安全区数值。

首页可见：大面积浅黄色双边框；章名、游戏名、口号和三关清单堆在同一面板；角色置于路中央；全身份链和底部当前身份重复；继续、重玩、整备、设置各占大按钮。字体尺寸有区别，但材质与框形高度重复，缺乏游戏入口的鲜明主次。

战斗可见：标题被黑色顶部遮挡覆盖，右上微信胶囊与HUD相交；武器/队友占第二条通栏板；山石损失与精锐标识、血条发生重叠；提示落在远离队伍的底部。这里能确认遮挡与当前排版，不能由一张图断定提示一直常驻，也不能评价实时帧率。

源码核对：Game.ts 使用720×1280 + FIXED_WIDTH，通用 panel() 为浅纸色双金线边框；屏幕差额 edge 仅按可见高度计算。当前顶部元素依据固定设计坐标+edge定位，Game.ts与Platform.ts读取片段中没有设备安全区/胶囊的布局计算。UI节点和手动点击命中矩形分别创建，改变排版时两者必须同源。

## 3. 一个明确的视觉方向

方向名：**轻量三国军阵**。

保留暖色世界和已有蓝色主将，UI采用深墨青/暗蓝的紧凑承托，少量旧金作重点，朱红用于出征或战果。军旗、令牌、甲片边缘是可选造型语汇，不做满屏龙纹、厚金雕花或伪古董做旧。暖纸色保留给短战报和内容卡，不再铺满首页/战斗顶部。

首页需要情绪与主角吸引力，战斗需要低干扰和辨识度；两者共享图标、字体和控件语言，不必共享一个巨大面板布局。

本包 visual-seeds.json 只是建议色值、间距与尺寸起点，设计 agent 可调整并记录取舍。重点是新画面成立，不能为遵守一组色值牺牲效果。

### 字体与图标

标题可使用一套获得使用许可的有力量中文展示字形；动态数字、按钮、损失、技能状态使用清楚的正文/数字字体。不要全界面书法，也不使用细金字直接压在浅黄路面。

390宽稿的建议起点：主行动18–20、正文14–16、辅助12–13、兵力数字28–32逻辑单位。一般按钮点击热区至少44×44，暂停可见图标24左右、点击区44。以上为本项目设计目标，不是根据原PNG像素倒推的规格。

若需要特殊字标，可单独导出少量标题矢量或图形。不得共享/打包容器字体文件，也不要把完整CJK字体随意塞入运行包。

## 4. 首页重新组织

### 目标层级

第一眼：主将 + 游戏标题。
第二眼：现在该去哪 + 明确主行动。
第三眼：整备、重玩、设置。

删除当前巨型标题底板，把游戏名称作为独立字标，章名“荆州立足”作为小标题。“带兵破阵，逐鹿三国”最多留一行。不要同时显示全三关名称串与全四阶身份串，再加当前身份。

主将保持原角色，优先复用现有正面/侧面肖像资源（确有资源才使用）；未有合适肖像时保留背向构图，不能生成一张完全不同的人物充数。让军旗、营地一角或既有远山作为承托，首页可不继续复用纵向奔跑路面。背景大图不是必交项，先靠重构已有场景和UI完成。

主行动区靠近拇指可达位置但避开底部手势区。当前任务/身份在按钮附近组合呈现，例如“领队 · 下一战 夺粮立营”。当前状态来自既有数据，不写死第二关。

二级入口用有标签的紧凑图标或小按钮。只有已解锁随军队友时才有现有整备入口；若为了可发现性要调整该条件，单独提议，不静默改变逻辑。

### 必须保留的状态与语义

- 新存档：开始出征 → 现有首关。
- 已有进度：继续征程 → 现有下一未完成关卡。
- 有待完成整军：主按钮按当前动作继续整军/建营/驻防，不能直接跳过其存档状态。
- 三关和驻防已完成：返回驻地/现有结尾入口。
- 重整旗鼓：当前是打开既有关卡重玩选择，不是删除存档。可改标签为“重玩关卡”。
- 设置保留音效、震动；BGM开关不恢复。
- 保存失败/加载失败提醒保留，不能为好看而隐藏。

## 5. 战斗HUD重新组织

### 布局起点

全屏环境允许延伸到系统遮挡后面，所有游戏关键UI放在归一化的有效安全区域里。优先使用胶囊下方的紧凑HUD，不把标题塞到胶囊和灵动岛之间的狭缝。

以390逻辑宽为参考，HUD建议总高约72–88，不含平台预留区。第一行容纳兵力、阶段/行程、暂停；第二行容纳武器阶级、自动觉醒状态和随军队友。尺寸不是死值；短屏必须重新排布，不能一味缩小文字。

“兵力24”是本截图示例，新稿必须同时检查1、24、48、256。数字保持稳定列宽，升级/受损时轻量变化，不能跳动到别的控件下。

行路阶段可用短进度线与“夺粮立营”。Boss阶段把行程区域换成Boss身份和血条；优先复用布局，不叠加第三条通栏纸板。Boss血量读取现有数据，不做虚假动画血量或提前显示胜利。

武器可用真实兵器小图标+“长枪Ⅰ/长刀Ⅲ”。队友用小头像+短姓名；没有队友时收起，同名Boss本场待命时呈现“待命”而非假装出战。不得添加点击施放技能、魔法值、充值、战力评分。

觉醒是自动六秒状态。图标/细环/高亮要传达“正在生效并自然结束”，不能看成待点击的技能按钮。

### 读数与战场的关系

暂停必须随时可达，热区避开胶囊。非交互HUD不要吃掉左右拖动输入；不得将一整块透明面板都变成拦截手势区域。

主将、队友、48人阵型、刀刃接触区、数字门与危险预告都作为设计底图中的保留区。UI不靠缩小队伍或移动真实战场来腾地方。确需改相机/世界投影必须单列，当前批次不默认授权。

### 敌人、障碍与瞬时反馈

世界标签属于UI：精锐角标、敌人血条、山石名称与碰撞损失要分配独立锚点和最小间距。优先保留可行动信息（血条/碰撞损失），精锐可收成小图标；不把`−6`缩到读不出来。密集时可在限定范围内错位并加细连线，不移动角色或实际碰撞区域。

增兵 +12、损失 −6 使用较短的局部反馈。升阶可在武器图标附近显示一次短提示；不同来源仍沿用现有 BattleNotice 优先级，不触碰触发条件、持续规则与实际战斗事件。

教程仅在原逻辑允许时显示；先优化外观与位置，任何“只显示首次”的永久记忆更改须单独获准。本图只是10%行路瞬间，不能据此认定教程已经永久常驻。

## 6. 本轮交付范围

### 必交的四张核心高保真画面

H01：首页，有当前身份/当前目标与继续征程。
B01：普通行路，用截图同一状态（兵力24、枪Ⅰ、邢道荣随军、10%）对照。
B02：Boss战，显示本关真实Boss、武器身份、血量与暂停，战场不变形。
B03：三阶 + 觉醒 + 队友状态 + 当前重要反馈共存。

每张提供干净PNG与平台遮挡校验版本，不只给套壳海报。场景底图可以复用，但不能“盖掉原HUD后把受保护战场也遮没了”。

短屏补充：360×640首页和最拥挤HUD；本用户941×2048原截图比例另验遮挡。所有模拟机型参数注明合成；不得宣称真机已通过。

### 一页共用组件，不铺开全系统

主次按钮/禁用/按下、武器阶级、队友选中与待命、精锐与血条、损失/增兵/升级、暂停小面板、胜利新解锁条、整备选择卡、拖旗整军说明。

可复用到 pause/result/loadout/transition，但不强求本轮把十二个屏幕都做满高保真。首页和战斗先做到完整，其他给足规格供Codex照用。

### 给开发的交付

可编辑源（按实际工具提供SVG、分层设计或HTML/CSS；不得虚构已创建Figma文件），布局/状态/触区标注，设计参数JSON，运行素材与九宫格说明，逐屏行为映射表。

可选单文件HTML仅供布局演示：无需npm安装、不连外部CDN、不隐藏平台遮挡、手机上可检查布局。最终游戏仍由Cocos渲染，网页演示不能冒称微信实机。

## 7. 执行边界与验收

- 不修改游戏逻辑、数值、关卡时长、角色身份、敌我攻击、世界位置、存档键、奖励、解锁与音乐。
- 不新增需要后端/账号/支付的功能，不部署，不购买素材/字体/订阅。
- 不做四套近似概念让用户继续挑；直接给一套强方向并在内部打磨。
- 新增运行UI纹理优先控制在128KiB以内作为项目目标，任何超出需写明原因和净包体增量。高保真设计图不进运行资源。不要为了凑目标降坏角色画质。
- 所有关键文本、按钮可见区和热区都不与系统遮挡或底部手势区相交；按钮热区之间不能重叠。
- 游戏标题、真实兵力、暂停、武器阶级与队友状态在手机原尺寸清楚；无超长假占位字符串，但要测真实最长状态。
- UI资源轻量、可伸缩，动态文字不烘焙进大图；不以高成本实时模糊作为必要效果。
- 设计阶段无需运行战斗；Codex接入时只做相关布局/交互回归和必要短片，不默认十局长测。
- 用户最终检查的是图片/演示，而不是仅有一份漂亮措辞的文档。
