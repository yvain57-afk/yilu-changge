## 3. 面向玩家的完成状态

### 3.1 首页与继续游戏

标题保留《一路长歌》。一句目标：「从小人物起步，一步步当皇帝。」
范围说明：「起步篇 · 三关，拿下第一座城。」

主按钮按真实进度决定：
- 从未通关：开始闯关，进入 trial-01。
- 已通一或两关：继续闯关，进入第一关尚未完成且已解锁的关卡。
- 三关全通：再次挑战，打开可重玩的三关地图。

不再展示“仅开放第一关”“后续制作”“选角色后接入”。正常首页去掉“查看队伍与动作”等开发入口；保留独立评审地址或显式调试参数，不删除有用夹具。

### 3.2 关卡与晋升

|ID|目标|初始兵力|局内行路长度|首次胜利晋升|
|---|---|---:|---:|---|
|trial-01|拉起队伍|8|42秒行路＋Boss|布衣 → 头领|
|trial-02|拿下营寨|12|54秒行路＋Boss|头领 → 统领|
|trial-03|夺下首城|16|66秒行路＋Boss|统领 → 城主|

以上行路长度是基线配置，不是强制失败时间。不能靠加速游戏时钟把录像或关长缩短。

每一关失败均可免费重开当前关，按本关初始编制出征，不扣已获身份，不回第一关，不扣资源。

局内兵力重新编制，首次进入每关短暂显示“本次出征：N人”。不把前关剩余兵力自动滚入下一关。

### 3.3 胜利必须可以继续

第一关首次胜利：晋升头领；主按钮“下一关：拿下营寨”。
第二关首次胜利：晋升统领；主按钮“下一关：夺下首城”。
第三关首次胜利：城门打开、旗号更换；主标题“首城已得”；说明“起步篇完成”；主按钮“重玩关卡”。

每关提供次级重玩或返回，不增加下一关再确认页、强制对白或强制阅读。

存档先于动画写入。胜利后刷新、后台切换或立即点击下一关都不能丢解锁。

重复挑战已过关时显示“再次取胜”，不能反复宣称晋升或让身份倒退。全局身份始终由已通关的连续进度推导。作战外形可以沿用玩家已获得的最高外形，兵力与伤害仍只由本关规则决定；出征说明必须清楚。不引入装备养成。

### 3.4 锁关保护

选关显示“已通关 / 可挑战 / 通关上一关解锁”，关闭未解锁按钮。
真正开始一关的函数也验证 ID、有无配置、是否解锁、是否具备生产资源；不能仅靠灰色按钮防跳关。
主按钮、选关、结果下一关、重开、调试参数都经同一有效性检查。
调试隔离夹具可以选择关卡；普通产品入口不能公开跳关、改兵力、改 Boss 血或直接获胜接口。

第一关已有的山道、友军、门、木障、敌人和投矛 Boss 继续使用。

### 4.2 第二关：营寨

共用道路投影、友军、门、石块与木障；补充帐篷、营旗、木围墙和营门，组成可滚动的营寨场景。主色与第一关连续，不能靠换整屏滤镜冒充不同场景。远处营门从一开始就可辨认，近景营旗和围栏提供前进感。

普通弩手必须持有可辨认的弩，具备准备、蓄力、发射、受击/退出姿态；与近接敌兵共享基础比例与制作方式。击杀蓄力中的弩手可以取消攻击，已发出的箭继续按规则结算。

营寨弩将：横向弩体、与投矛头目不同的肩背轮廓与瞄准姿态。沿用已有左、右、中固定区域攻击配置；不把他再画成拿矛的人。蓄力、弩箭飞行与命中预告读取真实模型阶段。

胜利：营旗落下、自方旗升起，主角呈现统领阶段。镜头/小过场短且可继续，不增加营地经营界面。

### 4.3 第三关：城门

复用适合的路面、门值、友军和环境小物；新制城墙、塔楼、门洞与旗号，形成从城外走向城门的空间。门洞是关尾目标，不能全程只摆一个等大的图标。

守城主将：以弓和肩甲形成独立轮廓，保留已设定的瞄准与左右攻击组合。第一版共用投射物/预告代码，不新做技能系统、盾条、召唤阶段、主动按钮或骑兵操作。

胜利：城门开启，旗号改变，角色获得城主外形；显示“首城已得”。结束为三关真实内容服务，不制作后面没有关卡支撑的动画。

## 5. 公平性与呈现不能退化

保留256真实兵力、48可见且包含唯一主角；伤害由发射时真实兵力决定；横向位置确定射击通道；无隐藏身份加成。

受阻门仍为覆盖半侧入口的一次原子事务：先清障判定和实际损失，归零则失败，否则应用一扇门收益。快速横移不得重复拿收益；中心边界约定和选择指示一致。

木障可射毁，山石不可射毁且挡箭，敌人按近目标先命中。山石和所有接触对象提前显示实际损失。

Boss 和弩手各动作帧的可见身体/装备要覆盖其真实可命中区；不能把首关四帧盾牌的宽度常量直接套在两个新 Boss 上。先量实际透明裁片轮廓，配置各自缩放/锚点；变化不得偷偷修改命中规则。

预告的来源、范围和时序来自实际攻击状态，锁定后不追踪玩家；投出后的箭不因原攻击者退场而消失。多个来源同时有预告时按 source/id 管理，文案不互相覆盖，也不能把弩箭统称“投矛”。

攻击者出手动作与真实弹道来源一致。装饰、动画、音效不额外结算伤害，不推迟命中，不让本来打不中的通道出现命中特效。

晋升身份从布尔改为明确阶段后，必须核对第一关回放、第二关和第三关均使用同一美术语法，不能回退到较旧的细碎立绘/部件表现。

### 最先比较的最小改动候选（不是已验证结果）

候选 A：只改 `trial-02` 的 `obstacle.id=101`（17秒、左侧受阻门）未清障损失 `10 → 5`，先不动它的HP64、最后受阻门损失48、Boss HP1800及射速。

意图：减少早期一次失误被后面多次倍增放大的损失，而非把最终风险门做成可直接硬撞的奖励。

算术示意，仅在后续路线与其他损失相同的条件下：
- 原路线：28人 → 扣10后倍增为36 → 另损8为28 → 倍增56 → 末门扣48再倍增为16。
- 候选路线：28人 → 扣5后倍增为46 → 另损8为38 → 倍增76 → 末门扣48再倍增为56。
- 在该首个受阻门前28人的条件下：清障可得56；安全+20得48；未清障新结果46，仍低于安全路。

这些是条件算例，不是新模型模拟、真实通过率或全状态最优性证明。策略会随状态改变，必须重新运行。其他可达兵力区间也要检查路线收益，尤其不要让硬撞在所有情况下都优于清障/安全门。

若候选 A 在正常路线和晚换路中达到合理时长，采用它即可，不为调参增加新系统。若不成立，优先继续比较少量第二/第三关静态配置：障碍位置、HP、固定损失、加法门值、Boss HP。每一候选均重跑相同路线并保存结果，只保留一套默认正式配置。

本轮允许第二/第三关上述范围的实测调参，无需逐个数值请示；模型公平性合同和首关基线不变。所有变更在数据对照中明示，不改断言来伪造达标。

### 本轮节奏验收目标

以下是制作目标，不是当前性能/结果：
- 首关保持已有最佳/安全/晚换路的合理节奏，不为三关统一而重做。

每次修改先跑受影响测试/类型检查；成批接入后做必要构建和局部试玩。最终内容稳定后运行完整回归和十局验证。若最终验证后又修改影响运行的内容，针对相关证据重跑，不沿用失效结论。

过程中可以简报真实进展，不能只交一张大立绘或一段第二关开头就结束。候选图和截图自查后继续，不重复请求用户批准同一角色。新增付费、权限、部署等仍需停受影响部分。

## 10. 必须补充的回归

原43项保护不删除、不skip，不弱化断言。依新三关范围调整“只开放一关”等旧范围检查时，注明是本轮范围变更，补上更完整的锁关、继续和结果验证。

关键新增用例：
- 全新档从第一关开始，二三关锁定，直接调用普通入口也不能进入未解锁关。
- 第一关胜利立即保存并解锁第二关，主按钮进入第二关，不循环回第一关。
- 第二关晋升统领，第三关晋升城主；标题、角色外形、场景、Boss和武器均对应。
- S2-B存档升级后保留第一关、最佳和设置，首页继续第二关。
- 第一/第二/第三关失败分别按8/12/16重开，不丢全局晋升。
- 重玩旧关不降身份、不伪称再次晋升、不重复写错最高阶段。
- 第三关之后没有越界下一关，完整结尾与重玩入口可用。
- 切关、暂停、后台、取消触摸、败退/晋升动画、资源加载异常、存档写失败均有实际覆盖。
- 弩手与两个新Boss的预告范围、发射、飞行、可取消条件、击败清理及可见命中范围一致。

- 计时上限针对固定测试策略；坏路/极低兵力仍不能被隐藏超时强制结束。

至少一次真实触摸完整走完三关，必须通过正常输入和自然胜利解锁，不用改档串联。

最终十局真实浏览器战斗分布建议：第一关4局、第二关3局、第三关3局；另保留顺序三关/跨关/刷新链路证据，可以与十局记录复用同一真实运行，避免重复劳动。三关实际失败分别覆盖；不要以规则模型十局替代浏览器十局。

记录设备、视口、每局时长、兵力、帧率、draw calls、节点、池、纹理/缓冲和JS heap。新增关卡会增加部分资源上界，允许合理增加；预热全部场景后重复轮转同关不应持续增长。不直接硬压回首关152节点或19.53MiB等旧单关数字。

60FPS为目标，目标手机持续低于30FPS不通过；缺真机就明确未验证。桌面十局S2-B结果不能直接用作v0.3性能结论。
