## 1. P0：接触可达性与兵器形变，统一修

### 1.1 已证实的缺口

- weapons.ts 长刀 near=.85，model.ts 前两Boss最终bossDepth=.9，且候选只按目标纵向点判断，导致刀刃不能命中。杨龄有step_thrust，能够缩到.35，因此缺口并非全Boss一致。
- 队友的攻击原点比主将靠后35/104≈.337。邢道荣斧近战上限到主将前方约.513，即使显示在挥斧，也到不了静止.9处的Boss；赵云在此原点下也可能依靠枪芒。复现详情见证据。
- BattleView.hero() 活跃帧对Boss直接求目标点，刀随后另改挥动尖端；诊断spearState在刀尖改写之前记录。debug仍取常量MELEE的枪范围。这会让调试画面与真实刀判定脱节。
- weaponSprite()按“目标尖端到握柄的长度”计算贴图缩放，兵器可能在出招中伸缩。应当以固定兵器长度和姿态移动接敌。

### 1.2 玩家应当看见的变化

长刀挥下时，刀刃真正进入Boss身体/装备的有效受击表面，产生本次meleeHit；刀气仍可继续存在，但同一攻击同一目标只结算一次。

邢道荣先提斧、适度迈到侧前方、挥斧接敌，再回侧后位；赵云有清楚的前送枪尖与回枪；陈应保持投掷定位，不能为了全员近战强制变成斧兵。

距离不够、方向不对时应自然落空。不存在自动跨通道追敌、兵器伸长至任意目标或虚假格挡。

### 1.3 最小实施路线

新增或提取一个小的共享战斗姿态/几何模块，例如CombatGeometry.ts。先检查本地是否已有等价模块，不为命名重写工程。提供同一来源的 actorAnchor、grip、edge/tip、近战有效体积、Boss受击表面与debug数据。模型先更新，渲染只读；箭与波仍使用既有独立投射物算法，不借此重写全部碰撞引擎。

先保留枪1.1、刀.85的差异和既有DPS。首选调整真正的接敌动作：
- 三Boss都要在每个完整攻防循环内给一个短刀可达的接触窗口。前两Boss可在既有收招/近身动作里从.9向.75附近实际进步，约.1的安全余量作为调试起点，随后退回既定待机位；是候选动作距离，不是已经验证的最终数值。
- 窗口应覆盖至少一轮玩家攻击，初试约.7秒，尽量在现有恢复段内安排，不额外插入长停顿。陈应仍能远攻，不必全程贴脸；杨龄保留原进步直刺特点。
- 近战队友从既有侧后原点向前做受控小步；邢道荣初试约.35–.4个纵向单位，赵云可更小。必须在模型里体现攻击原点变化，身体和握柄同步，不单独放长武器。输出姿态变化不改变队伍受伤中心、数字门选择中心，不赋予额外闪避或无敌。
- 本地若已有基于身体前缘的纵向受击形体，先测量和复用，禁止一边增加隐形体积一边再放大近战距离。采用另一种等价接近办法时记录理由并通过同样接触断言；无需重新询问用户。
- 不为打中Boss提高伤害、放宽全部通道、缩Boss血量。地形和木障的现有遮挡顺序保持。

### 1.4 固定长度与共享锚点

每把兵器的长度由资产设计/角色尺寸定义，透视引起的统一缩放可以保留。不得按“想打到多远”动态改变武器长度。

手柄跟随逐姿态测量的手部锚点。刀刃/枪尖通过固定长度与旋转、身体实际进步生成。来源中的ArtAtlasV05.ts、VisualConfig.ts及源图不在本反馈包，Codex须在本地读取，不按截图猜原图锚点。

刀的有效区域应吻合主要挥斩弧，枪为窄的前刺区。debug显示当前装备、真实原点、有效弧/尖端、目标受击表面和命中点，不能继续通用一套长枪矩形。弧线远近差异允许使用有限采样做连续扫过，不能只测跳跃后的一个点造成穿过漏判。

近战、波共用(sourceId,attackId,targetId)账本及一/二阶1目标、三阶2目标预算。近战吃掉名额；特效与拖尾不能增加伤害。攻击创建时冻结武器、阶级、伤害和瞄准方向，主动位移遵循现有可移动近战语义；出手后的波不继续追踪手指。

### 1.5 通过条件

- 长刀对三Boss均存在合法近战命中；重点复现第二关，没有弓兵也能看见主将meleeHit(boss)。
- 第二关携邢道荣出现近战斧击；赵云近战在正确距离有命中；陈应仍有真实投掷。仅有companionHits总数或waveHit不算近身证据。
- 同一次攻击的近战与波对同一目标不重复扣血，山石/存活木障保持阻挡；越界挥刀必须能落空。
- 正常原速片段和短debug叠加可对应同一攻击ID、主将/伙伴出手、碰到的位置、事件与血量变化。画面关debug后没有巨大红框。
- 兵器长度在同透视深度的姿态间保持稳定，握柄不脱手，不自动伸到目标上；必要的手部动作误差在390宽近景裁切下不可显著跳动。

## 2. P1：补能看得见的动作与成长，不重新生产整套美术

### 2.1 必需动作资产

优先级：主将长刀上身 → 邢道荣随军 → 陈应投叉/赵云快枪 → 三Boss握柄校正。

长刀不再复用spearHero上身加旋转。做备战、蓄势、挥斩、收招四个独立关键姿态，姿态间按真实攻击tick插值。衣服阶段复用同一动作骨架/分层部件，不重画脸、场景和所有弓兵。当前已有的多阶服装都须能持刀，不能只修一个阶段后回营又变枪。

三名队友按风格复用已有形象，分别补随军背向/侧背的准备、蓄力、出手、回收。底层继续共享图集和有限帧；移动下肢可复用已匹配的步态。取消ally一律取同一Pose3的分支。投叉后短时间手空，再备下一叉；斧有身体与手臂带动；赵云出枪和收枪分明。

Boss不重新选型。针对当前phase帧逐个测手部锚点，近身动作走固定武器长度及实际身体位置。背向与正向不能随意镜像导致武器换手/身份变化。

### 2.2 局部命中反馈

命中点来自实际接触事件，与本次动画一致。使用短火花、受击抖动/姿态、轻残影；画面先能看见接触，再增加美化。不新增手动弹反、不制造格挡成功假象。

默认不做整屏震动和全局hit stop。需要局部停顿时只影响角色的短受击呈现，不能停输入、延长无敌、推迟下一次规则命中。敌我命中与未来危险不能被白闪遮住。

队友处于侧后独立位置，其头肩与武器至少在8/24/48人数的正常镜头中可辨认；脚底名签只在入场/换队友时短暂显示，不每击打一行字。表现位调整须映射回共享攻击原点。

### 2.3 小屏成长信息

当前视频的主要成长信息挤在顶部一行“武器/阶级/觉醒秒数/队友”，背景上的刀气很薄。保留短信息，减少依赖长文字：
- 武器状态压缩为图标+I/II/III或一/二/三阶。加到既有HUD里，不新增长卡片。
- 精锐保留明确可见标识；首次击杀后显示约1秒的“击败精锐 · 长刀二阶”，一次光带从实际被击败位置到兵器，不从无关主角脚底凭空开始。攻击数值按既有规则立即生效。
- 三阶用可见但不挡路的锋缘/形态变化。六秒觉醒仍由三阶主将首次命中Boss触发；瞬间明确提亮甲胄/武器约.3秒，随后细环或短条显示剩余时间，结束淡出约.2秒。无强制停顿、无新按钮、无无敌。
- 首次提示只在出现相应规则时说明“破阵觉醒 · 6秒”，最多附一句“武器三阶后命中敌将触发”；不要在战斗中弹长说明。
- 优先级：危险与实际损失 > 升阶/觉醒 > 出征/普通增兵。多事件同帧不能让增兵文本立刻覆盖升阶。一次可见重点提示，低优先级合并或短延后，显示必须符合当前状态，不在觉醒结束后再播放“开始”。
- 战后显示本次真正新增的武器/队友及立刻上阵入口；重复挑战无重复获得假提示。保留现有奖励幂等与选择保存。

不为凑精锐出现百分比改位置，不改两次升阶条件和六秒时长。

### 2.4 武器差异的处理顺序

本轮先靠动作、形状、命中点建立枪刺/刀扫/斧重/叉投/快枪差别。枪刀均36tick、伤害倍率以及同階伙伴20%理论DPS先不变。

仅补一份战斗局部统计：hero.melee实际伤害、hero.wave实际伤害、archer实际伤害、companion按ID与melee/wave分类的实际伤害。只记录实际HP差值，不以命中次数推算、不计过量伤害；不得影响伤害计算。每关最后输出一次聚合值，不逐帧输出。

当前弓箭hit.amount=0，需从实际扣血位置填actualDamage或独立只读统计，不能把零误认为弓兵没有贡献。近战与wave已有amount以实际扣血值为准；break/upgrade不再重复计伤。

统计用于下一次决定平衡，禁止本轮因为主将占比小就削小兵或增加隐藏系数。

### 2.5 通过条件

正常速度、360/390宽：长刀不是举枪换刀片；队友出手可辨认；升二阶、三阶、觉醒开始/结束无需一直盯小字；低优先级提示不遮危险。名将大小和整体美感留给用户集中反馈，本轮不把Boss显大作为必须整体缩放的已验证故障。

## 3. P2：同版本手机试玩与最低必要测试

### 3.1 本地验证，按风险运行

现有89项结果属于v05，保留日志，不写成新版本通过。新增包内contact-v051.contract.test.ts；导入前核验本地接口并与已有测试避免重复。可使用项目现有tsx入口运行该文件，具体命令以本地package.json和run-local为准。

最低集合：
1. 刀/枪×三Boss可达性；近战伙伴的合理位置；超距离/偏侧不误伤；保持同一命中账本、地形遮挡。
2. N=1/N=2/N=48/N=256计数、同名待命、已出手波快照与暂停冻结；尽量复用现有用例。
3. 升阶/觉醒/奖励/旧档未知字段及bgmEnabled=false等回归，不重写经济与存储。
4. 资产及池有变化，做一次15–20秒高密度片段，加三次快速重开。记与当前同场景可比的帧间隔与资源数，不用“总数大了”自动断定泄漏。截图/夹具必须标清。
5. 整合完成后一次自然三关，流程示范枪+无伙伴、刀+邢、枪+陈，读取通关存档补赵云短段仅在必要时。正常流程优先复用原控制器，不能为了表演近战使用内部改HP/时间接口。确实需要调整输入策略时记录，不把脚本当新玩家盲玩。

录像复用；接触段从该录像截取原速片段，逐帧核对另做调试录制即可。一个局部失败重跑相关项，源码再变更才标记需要受影响重验。不得调用旧verify-v03及历代整套流程累加，不默认十局。

- 读本机已安装Wechat开发者工具技能/CLI说明；使用现有项目路径、compileType与同一测试AppID。不捏造参数，不把本机localhost链接发成可供手机互联网访问的地址。

## 4. 交付清单与停止条件

交付当前三关可玩版本，附一个简短评审入口，最多一份连续三关录像、一段未覆盖的伙伴补证，以及正常小屏前后对照。

评审摘要必须分开：原包报告、此次本地复测、真实手机状态、用户主观判断。只给少量必要数值，不把89→更多测试数量当成果。

不可省略：刀对陈应的实际近战事件与接触画面；同一攻击不重复结算；随军近战动作可见；真实武器长度与调试一致；BGM保持关闭；存档无倒退。

可后续处理：Boss整体大小、进一步调整枪刀数值、全武将动作、音乐、音效替换、完整历史主线。当前骨架既已可玩，不重新推倒。
