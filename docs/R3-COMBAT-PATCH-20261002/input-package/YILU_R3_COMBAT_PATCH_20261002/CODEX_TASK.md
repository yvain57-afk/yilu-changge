## 2. P0-A：修敌军真实出现与公平命中

### E01 生命周期冲突
修改 battle.ts 的 spawnCourse/spawn/updateEnts，详见SOURCE_AUDIT。
- 删除或重写“elite且z>40即清理”的错误条件。实体预取、运行、渲染预算和离场是不同概念。
- 已从route消费的事件不能无原因永久丢失。预算不足应保留事件队列、合并为后续合法小波或延迟生成，不能生成后清空。
- 活敌允许清理的原因必须显式：合法退场/越过后方边界/战斗终局；死亡播放完另处理。尚在前方的活弓手不能按“太远”删除。
- 屏外可准备资源；开始锁定/攻击的敌人必须已进入可读战场，不出现隐形伤害。
- 记录每个enemyId与waveId的planned/spawned/visible/acquired/warn/release/impact/death/despawnReason，以及被威胁预算延迟的原因。
- 对正常route从远到近测试所有7兵种，不能只手工创建z=10的敌人验收。无己方攻击的诊断夹具保证每种合法威胁确实能出招；开火夹具允许提前击杀敌人，记录真实死亡原因。

### E02 按兵种区分距离与状态
在现有 EnemyProfiles/EncounterDirector/battle 上实现COMBAT_SPEC，不引入另一套战斗引擎。
- 轻兵、近卫、盾兵先接敌，再做有预备动作的近战，进入reach才能产生伤害；保留攻后回收/再次攻击，不以“碰一次自动死亡”冒充战斗。
- 近卫/盾兵在z=18的预警不得直接扣玩家兵力。没有定义光波的刀兵禁止隔空伤害。
- 弓手有真实抬弓、锁定、发箭、飞行、命中/落空；箭从其自身武器发出，锁定后不继续追踪主将。
- 骑兵有冲锋方向和实体经过；旗手保留原可破坏增益；机关按地面范围与时间执行，禁止整屏瞬时扣兵。
- 威胁预算覆盖到实际命中结束；射手死亡能取消未释放的攻击，已经射出的箭继续飞，除非有明确可见的拦截规则。
- 胶囊/投射物用扫掠检测防穿透；同attackId/subAttackId只结算一次。成组箭雨与群近战不得每渲染帧重复扣兵；用挥砍接触/箭矢命中事件结算。
- 预警可达性检查覆盖实际最早碰撞时间、己方队形脚点、已承诺的其他危险及当前/即将到来的墙段。无安全路径就延后或换可读攻击组合，不制造不可躲惩罚。

### E03 防守反馈语义
沿用军队兵力这个生命资源，不新增主将/随军独立HP系统。
- 只有实际结算伤害>0才产生受击反馈；空挥、护甲完全挡住、处于预警中和己方出招都不触发hurt。
- 兵力损失主要由受影响士兵表现。确实击中主将/附近队列时可短促受击，不要每减1兵就让主将跪地。
- 受击动作是轻微后仰/护住身体/短暂闪烁，随后恢复合法攻击阶段；不能因受击重复触发release、丢掉已出手弹体或重新播音。
- 倒地/败退只在最终失败已成立时播放；七星灯等保命效果先结算，不能先倒地再随意站起。
- 普通攻击保持wind→rel→rec→run/idle，rec是收回兵器，不是Hurt/Fallen/Spent/Yield。
