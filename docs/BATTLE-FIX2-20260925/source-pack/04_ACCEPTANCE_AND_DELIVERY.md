# FIX2 验收与交付

## 1. 六组需求都必须独立回答

攻击动作/兵器光波、箱子信息、所有门值排版、顶部建筑、单门封顶/有效窗口、隔离墙分别写结果。状态使用：通过、部分完成、未通过、待实测，并附实际证据。不要用“本地可修复项已过”回避用户尚未认可的美术。

纯视觉改动与门规则改动的测试分开。前者比较同状态同输入模型；后者允许有意的收益与下游变化，核对因果及账本。旧断言因新规则更新要说明，不能无记录删除。

## 2. 必交媒体

**四组同状态对照。** 普通攻击；门箱同屏；双列/墙端；密集连续门与接敌。每组含FIX1或本地更晚基线、FIX2、屏幕尺寸、关卡、时间、兵力、兵器、火力阶段及自然/夹具标记。视觉对照使用等价状态；收益差异另做曲线或日志，不能强行说所有模型相同。

**30—45秒原速展示。** 覆盖武将新动作与波形、门持续改值、箱文字与耐久变化、连续+1、墙端、顶部原问题位置。允许按标注切点从一次自然三关录像剪辑；不要宣称30秒内自然连续发生所有事件。缺少另一武器时加一段明确的定向演示，不拼装成自然单局。

**完整自然三关。** 开局、胜负、原有过渡和存档保持。沿用正常合法输入，不注入兵力、血量或时间。展示片必须能追溯到该次录像的时间点。后台、极端数值等未覆盖的单独补定向证据。

顶部建筑的问题至少提供8秒无切点片段。攻击与特效同时给原速和可定位的帧号，原速是手感判断依据。保留真实音效，无BGM。

## 3. 封顶与增长报告

填写templates/CAP_AND_PACING_REPORT.json，说明旧上限、来源文件/行号、旧依据是否存在、新window策略、数值护栏及逻辑容量。旧版观察已附，不再要求用户查参数。

比较A当前基线与B新策略，每个问题门记录真实可見且可读、可命中、第一次命中、经过、累计伤害、门值变化、领取量和无效停涨时间。若再调局部静态参数，写入B变更清单。一次试验或自动最优路线不包装为玩家胜率。

## 6. 不得混淆的四个结论

代码回归通过、美术资源已存在、开发端视觉检查通过、用户审美认可分别记录。素材未完成、不好看或不符合兵器身份，不能靠“测试通过”覆盖。手机未实测按待验；这不会阻止提交已完成部分，但不得报整体全部通过。
