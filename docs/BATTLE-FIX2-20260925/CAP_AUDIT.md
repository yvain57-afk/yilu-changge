# FIX2 封顶与容量审计

核验对象是最新本地累积源码；父代理已保存 `.cache/BATTLE-FIX2-20260925-baseline`。当前没有该文件的 Git 提交历史可用于恢复设计推导，旧代码保持在基线目录。

旧 `runnerConfig.ts` 共15个 mutableGate：第一关5个（8、8、4、4、4），第二关4个（8、8、12、12），第三关6个（均8）。`runner.ts:hitTarget` 以 `Math.min(maxPositive??64, value+points)` 停涨，并到顶清除 progress；`samplePacing` 的封顶瞄准时间只看成员横向对准与射程，既不是手指停留时间，也不验证前方遮挡。当前配置无尾部二次改写。v2来源reference规则有默认64和总人数256；v09规格明确这些不是原版公式。未找到4/8/12的独立推导依据。

四种量分别为：单门上限4/8/12（游戏规则）；add中的总人数256（另一个游戏容量）；最多48个可见成员（模型中有实际加权代理，权重和等于人数）；数值技术保护（旧实现没有独立有证据的保护策略）。显示预算不能用来截断奖励。最大512弹丸和64普通敌人是对象预算，保持不变。

新策略：当前15门显式`growthStrategy:'window'`，忽略保留的旧maxPositive字段；`capped`保留旧语义。缺策略但带maxPositive的旧配置仍按capped兼容，缺策略且无旧cap字段按window；window不使用空值回退。真实累计伤害、整数跨阈值、余数、同帧一次碰门与错过不补发保持。

## 合法三关上界（保守，不是新游戏性上限）

当前最大射程8；48代理最后一排脚点-2.75；门错过宽限.15，弹丸单步最大越界.15，口偏移.05，合计不到12秒。15个配置中的最晚普通门均至少早于路线终点4世界单位，故门不会在停步后的无限战斗里持续存在。每slot正常发射最多ceil(12/.2)+1=61次；额外用61次覆盖.2秒全局接触宽限造成的死亡重生，再加该关全部目标数覆盖增员/负门/援手的slot变化。每次伤害用最大2.5×赵云系数1.5=3.75，即使普通兵实际不带此系数也如此高估。

把该关所有固定人数奖励（含全部链门）和所有正初值都预先加入种子；然后对每一门按 `N <- ceil(N * (1 + 每slot最大伤害 / damagePerPoint))` 递推，忽略负门、敌损、遮挡与互斥瞄准。任意实际领取顺序都被这个全收益乘积覆盖。三关种子25/43/70；所得上界354,783,529,499 / 4,023,782,714 / 1,321,985,683,997。取最大上界两倍的下一2次幂：**4,398,046,511,104（2^42）**。它比证明上界高，不用于常态控制增长；单发最大伤害4倍该值仍远低于Number安全整数边界。触及保护须记录numericGuard原因并显式报错，不能静默夹值或丢奖励。未来关卡/阈值变更会重算该界并检查精度。

旧存储只有Book(best/cleared/settings/profile best)、Growth(装备/解锁)、Campaign(过渡/会面)；没有Journey/Runner未结算在途存档恢复入口。故不虚构旧门迁移，也不回补已丢命中。字段spread保留的未知存档数据不在本代理改动范围。父代理负责仅runnerBest容量兼容；legacy best仍按原256。

呈现接口只新增发射时冻结的weapon/actorId、正式发射recentFires（24ticks）、只读nextFireAtSeconds和issued统计；没有改变伤害、起点、速度、射速、碰撞。

## 当前验证结果与复现

`CAP_AND_PACING_REPORT.json` 记录6对同输入、真实弹丸的单门短夹具。A实际加载备份FIX1核心；B加载新核心。`PARAMETER_DIFF.json`及工具中的deepEqual断言确认没有改damagePerPoint、位置、速度、敌血或奖励。示例：8人连弩的l1.g1从旧+4变为+53，旧5.033秒封顶空耗消失；l3.g1从+8到+23，48人火矢该门从+8到+157。低兵力或偏晚换向仍可能撞负门失败。首次可读时间明确为空，留给浏览器实图核验。

`CAP_MODEL_PREFLIGHT.json` 另记录现有runnerSteer固定策略各一遍纯模型预检：三关全胜，结余533/16/125；峰值弹数236/52/227；无numericGuard。第一关实际超过旧256，说明移除总人数截断不是仅增加无用参数。该结果不是自然录像、手动难度或用户胜率证明；不用于擅调阈值。

41项相关测试通过（原32+FIX2新增9），记录于`CAP_TEST_RESULTS.txt`。开发中曾有一项发射身份测试误用会致死的负门，导致第二次发射不存在；改为零值门后验证相同tick消耗、换装、暂停和24tick清理，未改真实规则迎合断言。

复现A/B：`node tools/fix2-cap-audit.mjs`，脚本从随工程保留的`tools/fix2-cap-audit-baseline.tgz`抽出原核心到专用cache，仅用于导入对照，不覆盖当前源码。复现纯模型预检：`node tools/run-local.mjs tsx tools/fix2-cap-audit-preflight.ts`。报告含当前源码/参数SHA256与精确入口行号。浏览器可读窗口及最终自然录像由父代理接续。
