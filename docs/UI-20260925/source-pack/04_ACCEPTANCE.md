# 验收与交付合同

## 1. 状态口径

本包只定义检查，所有案例初始not_run。执行后才允许填pass、fail或blocked。没有真实构建截图、录屏、日志或模型断言支持就不写通过。概念图、伪状态、旧版本、模拟脚本、设备预览和真机实玩要分别注明。

交付分开报告：功能接通、视觉完成度、动态表现、规则正确、手机实测、性能/包体。某维度通过不能替代另一维度。未完成的美术明确列缺口，不用“基本优化”“全绿”概括。

## 2. 视觉必检

五个核心页及过渡/会面/弹窗同风格，书法只用于大标题，正文和数字易读；按钮主次清楚；不见重复主将、掉字、乱码、刘海遮挡、手势区按钮、建筑盖字、假资源与无效入口。

参考图与最终UI存在有意差异：三关替换第六章、真实卡片替换三副将、真实战果替换金币与星级、开放横移替换封闭三路。对照报告说明这些差异，不能把它们作为偷减界面品质的理由。

固定七组before/after：home、chapters、loadout、battle-normal、battle-contact、result、camp。相同视口与等价真实状态；若只有after，明确before缺失。每组附对应参考区域、完成说明、仍有差异。比对构图、材质、层次、角色尺寸、留白和信息，不虚构一个像素相似度分数证明“高度还原”。

## 3. 交互与规则必检

点击/长按/拖动结束不透传；主按钮防连点；选中、锁定、忙碌和错误与实际动作一致；卡片改变不自动开战，返回不偷开战。小屏、长文案、无队友和无成绩仍有可操作路径。

门的负→0→正、封顶、接触领取；箱耐久消耗与所得分离；连续+1单独接触、漏领不补；真实队伍出弹、旧弹不跟随移动转向；高人数权重不重复；边缘成员可发生真实接触；敌军未击杀不能删活；敌将双条件保留。每一类都需要真实状态链路或定向断言。

结果只读已确定事务；首胜/重复胜利/失败/最终关后续正确；保存失败、重复打开结果、过渡中断、重新进入会面不会重复发奖。

## 4. 动态与手机

自然原速录像中应看到跑动和出手动作、命中反应、增减兵、换装、门打正、箱破裂、建筑完整离屏后回收。静图上下跳不能当作动画完成。片段需要音效时保留现场声音，BGM关闭。

在360×780、375×667、390×844、430×932、768×1024示例视口核对适配；真实设备安全区来自运行数据。真机至少覆盖可用的异形屏和另一个手机样本，未具备的设备条目blocked并说明。截图不能证明实际触控、发热与听感。

性能记录同设备同构建的p50/p95帧时、最差停顿与内存变化；先比基线再定局部优化。建议目标流畅60fps，较低性能设备维持可玩的帧率并如实记录；不声明全设备保证60fps或零发热。装饰降级不能改变战斗规则。

## 5. 最小充分验证策略

开发中做相关检查，最终必要构建后跑一次自然三关连续流程；失败的尝试保留，修复后最终新流程需对应最终构建。短片从同次流程裁剪；未被覆盖的状态用隔离夹具并明示。无需把643项检查每改一处都重跑，也不默认十局长测。

`config/review_cases.json`给出结构化检查对象；`REVIEW_RESULTS.json`建议字段：caseId、status、buildId、runKind(natural/fixture/device)、device、viewport、evidencePaths、observed、knownGap。无证据的pass无效，blocked也需说明真实原因。

## 6. 交付目录建议

- `BUILD_ID.json`：源码状态、构建指纹、工具版本、构建日期和产物路径。
- `REALITY_MAP.md`：实际入口、字段/命令、资产及本轮修改的映射。
- `CHANGELOG.md`：按视觉、交互、性能、兼容性分类的实际变化。
- `ASSET_STATUS.md`和`ASSET_BUDGET.json`：复用/重绘/缺失，源与运行资源区分。
- `VISUAL_REVIEW.md`＋七组前后截图：对应参考目标，差异与待改。
- `REVIEW_RESULTS.json`、性能/输入记录及必要日志。
- `final-three-levels.mp4`与从同次裁剪的短片，明确原速现场音效。
- 当前可运行Web构建、微信测试构建或具体阻塞、已验证启动方式。
- `KNOWN_GAPS.md`：美术、实机、性能、流程和资源缺口，不藏在完成声明里。

最终回复只给已完成、证据入口、如何试玩、未完成与真实阻塞。没有用户授权不公开发布、不付费、不切换业务AppID。此文档本身不构成游戏验收。
