# 实施任务、数据合同与工程约束

## 1. 基线盘点与真实文件映射

以当前本地累积工作区为准。S1明确v0.9候选版本不等于远端HEAD，用户未提交修改应保留。先读适用AGENTS/PROGRESS、git状态、包配置和现有页面入口；不为完成本任务自动升级Cocos或Node大版本。

`REALITY_MAP.md`至少包含：实际运行版本与日期、每个页面的文件/类/节点入口、胜败/存档/奖励入口、现有资产目录、可运行脚本、未提交改动保护范围、当前真实规则与S2的差异。每个拟变更文件说明归属和目的，不伪造已经读到源码的结论。

| 工作单元 | 入口条件 | 实施内容 | 退出证据 |
|---|---|---|---|
| T0 | 当前工作区可读 | 核对源码/状态/资产/命令，保留before图，写REALITY_MAP | 实际本地版本、截图、缺口、改动清单 |
| T1 | 核对入口和素材状态 | token、安全区、组件；真实首页和短战斗样片 | 实际构建截图/录像；风格/比例/数据无误 |
| T2 | 样式能在引擎工作 | 首页、三关地图、整备和各自异常/锁定状态 | 选择与开局一致，所有按钮调用真实命令 |
| T3 | 世界显示链路明确 | 地景/角色/门箱/HUD/动作，坐标与命中一致 | 真实片段、占位调试对照、规则回归 |
| T4 | 核心页面可运行 | 结果/驻地/过渡/会面/设置/错误态；清理残留 | 首胜/重玩/中断恢复与场景切换记录 |
| T5 | 页面和规则接通 | 适配、性能、资源打包、定向测试与自然流程 | 本次构建、对照、录像、缺口及报告 |

阶段用于内部连续推进。一般UI尺寸、资源制作和文案映射由文档确定后直接做；不在每一页停下来让用户重新描述。付费、公开发布、新系统与确实无法自行解决的关键冲突才需要确认。

## 2. 模块职责与文件组织

以下都是建议职责，不代表仓库已有同名代码。可在现有模块内实现，或做必要的小范围拆分；不要为形式统一重写整个战斗框架。

- 页面协调器：当前页面、返回栈、弹窗、进出生命周期、输入屏蔽；只能有一个活动内容页。
- 展示适配器：读取真实模型和存档，构造只读页面状态。路径与字段逐一记录REALITY_MAP。
- 主题/布局：token、共享组件、逻辑坐标、安全区、胶囊避让、短屏布局。
- 世界表现：将模型位置投影至同一画布；角色、弹道、门箱、判定轮廓和标签都用该变换。
- 资产服务：沿用已验证加载管线，处理加载成功/失败、页面代次、引用与池复用。
- 测试入口：从当前可用测试体系添加定向断言，不凭本包任务名杜撰npm命令。

多个执行者有明确文件归属。UI与美术接入者不改伤害；世界表现者不改存档；平台者不随意动关卡事件。共享入口只由整合者修改。

## 3. 数据映射

`contracts/presentation-contracts.ts`仅定义建议视图合同，Codex需要绑定项目实际模型。禁止反向创造假经济数据使类型变得“完整”。

| 页面 | 需要读取 | 用户动作 | 缺失处理 |
|---|---|---|---|
| 首页 | 主角、真实身份、当前征程、待过渡标志 | 开始/继续、整备、关卡、驻地/设置 | 无状态时用新局入口；不补金币/等级 |
| 地图 | 实际三个关卡、解锁、模式成绩 | 选节点、出征/再战、返回 | 无成绩显示未挑战 |
| 整备 | 当前主将、可选同袍、现有兵器、选择与保存状态 | 选卡、返回、明确开始/继续 | 锁定与空队友可见；无真实属性不画 |
| 战斗 | 真实兵力、火力、门值、耐久、目标、Boss状态 | 拖动、暂停 | 无Boss时不画Boss条，无字段不填伪值 |
| 结算 | 结果ID、实际奖项、损失来源、记录、保存与后续步骤 | 下一步、再战、返回 | 无新增显示战果；无已知损失不编原因 |
| 过渡/会面 | 真实阶段和已完成标志 | 既有互动、下一步、跳过 | 不重发已发奖励 |

视图不可发奖、扣血或自动修改存档。用户动作进入现有命令服务，成功后从新状态渲染。主按钮双击通过命令忙碌态与幂等保护；鼠标点击与触摸合成事件不能让一次按下执行两次。

## 4. 流程与幂等

保留模型原有的胜负、发奖和恢复顺序。结果页只展示已确定结果；动画事件不承担唯一发奖责任。使用局ID/结果ID/事件ID避免重复渲染和重复反馈，不能仅用一个全局boolean屏蔽以后所有奖励。

整备卡片保持原有选择即保存。新金按钮是明确的开始/继续动作，与返回分开；pendingTransition存在时按钮文案和目的地必须一致。锁定关、失效同袍或未完成过渡不得被绕过。

页面退出时注销事件/计时/触摸，取消或忽略过期异步加载回调。暂停、恢复或切页要清空手势累计值。渲染复用旧组件时重置数值、选中、禁用、名字、头像、血条、透明度、颜色及动画。

## 5. 安全区坐标算法合同

1. 使用现有平台获取方式取得视口、安全矩形和平台保留区域；获取方法由当前引擎/平台版本核对。
2. 将矩形两个角通过同一viewport→canvas变换映射为逻辑坐标，统一轴方向。胶囊也经过相同变换。
3. 背景使用全视口；内容使用转换后的安全矩形，交互再避让平台保留区域。重复包含的顶端区域取约束并集，不能把同一状态栏算两次。
4. 页头/页脚固定在安全范围内，剩余高度给内容区；存在最小字号约束，中区不足时滚动。
5. 世界投影与输入逆变换在resize后同一帧更新。DPR只参与输出清晰度，不重复进入逻辑布局计算。

建议数学验证：世界点投影后再逆变换返回原值；已知脚点、门底、弹道与调试判定重合；触摸向右10逻辑单位在全视口都对应同方向可预期位移。具体允许误差在工程数值单位确定后记录，不能把逻辑单位和像素混测。

## 6. 世界投影与逻辑边界

现有透视满足目标时只改资源与分层。需要改透视时先集中投影接口，再一次迁移地景、角色、门箱、弹道和输入，避免各处散落不同缩放公式。不能只把精灵向下挪、放大但继续在不可见旧位置触发损兵。

长屏多出的空间优先放环境；物理时间、波次触发、有效可射击窗口、奖励经过时刻不因页面缩放改变。出现差异要记录，先校正投影/布局，数值优化另记参数差异。大队形的压缩展示需与真实可见代理/脚点方案一致，不能变成屏幕中窄队但实际宽墙。

正负门仍可被真实射击改值；正负门/箱子的结算规则按对象原类型保留。第二关只保留真实障碍的挡弹功能和开放口，不新增封闭三分路。音效并发控制、视觉合并提示只降低噪声，不合并奖励事务或改伤害预算。

## 7. 构建与源码保护

S1提供的已知入口供核对：`npm ci`、`npm run typecheck`、`npm run typecheck:core`、`npm run check:v09`以及`npm run build:web`、`npm run build:wechat`。本地脚本变更时以实际package.json为准。Node/Cocos版本按本地文档确认；不声称这些命令已在本次会话执行。

S1记录的图集加载兼容修复、资源优化与UV/锚点保护要求必须保留。新任务证据建议放`evidence/ui-20260925/`，新输出目录不要覆盖历史before/after、失败尝试、用户原资产和未提交文件。

依赖新增应有必要性、锁文件与平台验证。BGM不加载，公开发布不执行，共享材料不包含密钥/登录数据。不要借其他业务AppID跑测试。
