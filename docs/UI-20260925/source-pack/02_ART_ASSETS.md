# 美术资源制作与接入合同

## 1. 目标与现状

以`references/01_approved_visual_target.png`和用户选中的四张局部图为视觉依据。`references/06—07`的开发海报仅辅助理解，不覆盖正文裁决。所有附图均为概念参考；本包没有声称包含完成的立绘、序列帧、图集或Prefab。

观感重点为：有纵深的城寨与山河、统一左上方主光、蓝色己军/红色敌军、清楚的轮廓、木石金属材质、低噪声文字区、旧金主按钮。人物为略夸张比例的手绘游戏角色，近看有细节、缩小后有轮廓。背景与战斗角色材质要一致，避免写实背景搭配简笔画人偶。

首次盘点在`ASSET_STATUS.md`写清每个manifest条目的reuse/modify/create/blocked、现有路径、缺口和最终路径。清单中的名字是建议ID，不能拿这些名字证明工程已经存在资源。

## 2. 按资源组制作

### A. 首页与非战斗环境

首页背景拆成远景城墙/山脉、中景街巷/城寨、近景装饰；主将透明立绘独立。背景不得含主将、文字、按钮、手机外壳和永久UI。字标独立，不与主将合并。首屏主要人物姿态可采用已认可的背身或侧背披风构图；武器、服饰和身份仍来自已有主角。

关卡底图不含文字与节点。卷轴、路径、节点、锁、当前位置旗帜都是独立组件。只为已有三关提供景别与地标，不制作假的第六章。营地背景不滚动；结果背景独立控制亮度，预留标题和卡片区域。

### B. 角色与图标

头像必须与角色ID一一对应，源图推荐512×512，最终按实际显示尺寸输出。立绘推荐透明900×1400，不能靠大幅裁切脸部或脚部适配。

战斗角色优先复用现有合格图集。需要新增时，每个角色交付：行军、出手、受击/退场及必要转向；建议初始帧数为行军6帧、出手4帧、受击/退场各3—4帧，帧数是制作起点，不强制替换更好的现有动画系统。武器/手部与出弹锚点给出元数据。脚底对齐，帧间包围框可变但不能造成跳脚和身体漂移。不能镜像带方向性文字或左右手关键装备来掩盖缺帧。

主将、同袍、普通兵拥有不同辨识度；不生成图中三位名将替换当前主角。武器和奖励图标推荐256×256透明底，保持同一主光与轮廓粗细。任何文字或数值仍由引擎绘制。

### C. UI组件

金色主按钮、次按钮、页头、卡片、卷轴、弹窗按可伸缩组件制作。平直区域伸缩、边角不变形。九宫格边距必须写入manifest，未填写时由导入者测定，不能直接默认为0。

组件状态不要求每态另画一张图；可在底图上叠加边框/遮罩/选中勾实现。但禁用、忙碌、锁定既要看得见，也要真的限制操作。真实进度、头像、名字、门值、耐久和按钮字禁止烘焙到贴图。

正文采用项目可合法使用的清晰字体，品牌及胜败字标可用经过检查的美术字。字体授权与中文覆盖需核验。本包不附带字体文件。

### D. 战场与门箱

道路采用可重复纹理或地块；出口、入口、路缘在接缝处一致。树、栅栏、帐篷、塔楼独立摆放；高对比前景避开可操作通路。第二关的真实挡弹结构独立于普通装饰，开放口在美术上明确。

门为立柱、旗面、符号、数值、阴影和受击层。门面可蓝/红/中性，命中闪光保持正负识别。普通装饰柱不能扩大碰撞。四类奖励箱可共用一两种基础箱体，但顶部图标和奖励名必须不同；不能只换颜色。

连续+1门要有独立实体图；生成/通过特效是表现层，不能带来第二笔奖励。箭、连弩箭、火矢使用不同轮廓与尾迹，命中特效按模型结果播放，爆炸范围不凭视觉扩伤。

## 4. 输出与导入

源图推荐PNG；运行输出格式依据现有管线和目标平台支持验证。透明资源保持正确Alpha；检查白边、黑边、残留底色。背景不把整张源图原样常驻显存，先按实际需求输出尺寸与压缩版本。

每项记录：assetId、来源、是否生成/原有、授权说明、源尺寸、运行尺寸、透明性、锚点、切片边距、动画帧信息、使用页面、加载组、实际大小、状态。已有图片在UV/锚点上承担逻辑约束时，需遵守旧资源优化合同，不能粗裁后让碰撞或枪口位置漂移。

首次导入检查实际缩小后的轮廓、字体/符号、所有帧的透明边与脚点。必须在真实Cocos构建看，不只看源PNG。背景、卡片、动态文字与交互热区各自独立，禁止整张视觉总图铺底再盖透明按钮。

## 5. 资产缺口策略

已有资源合格则复用；风格明显不符就标modify/create。当前工具或权限不能生成资源时，继续开发可独立完成的组件、状态、数据与适配，输出最小美术需求包。可临时占位用于接线，但发布候选必须移除或明确标视觉未完成。不得擅自购买资源、付费调用服务或把未完成资产说成已交付。
