# v0.9 全局设计：把当前三关做成一款完整的小型三国游戏

## 0. 本轮决策

用户已经要求全局优化。此次覆盖产品呈现、操作流程、战斗信息、队伍与敌军表现、奖励成长反馈、地景、必要的节奏校准和移动端交付。新系统、更多章节、更多人物数量不属于这轮成果指标。

所有下列设计数值是本轮试制初值，需在实际屏幕校正。不能称为Last War原版参数、用户逐项批准值或已经验收的最终标准。

### 不动的产品骨架
- 三国人物与已认可角色身份、连续三关、已有队友和永久解锁。
- 同一跑道连续横移，移动决定瞄准/奖励/风险；不进入独立路线子场景。
- 射击改变正负门；箱子耐久与奖励分开；击破领取与经过领取按现有对象类型区分；连续+1逐个领取。
- 多成员真实出弹、战地装备变化、大队形的可见占位风险。
- 音乐关闭；不新增充值、广告、联网服务或账号。

### 允许整体重做的层
- 全部UI构图、角色展示位置、角色与普通兵的比例/间距、敌我接触排列、投影与地景组织、门箱视觉、动态反馈。
- 页面显示层的职责与生命周期，必要的小范围模块拆分。
- 不合适的门饱和阈值、奖励耐久、事件距离等可进行有限对比后调整；不预先把旧初值当成最终标准。
- 暂时保留的素材可以替换。保留源文件/版权/用户批准的角色辨识，不要求保留低质量的最终显示效果。

## 1. 产品应当让玩家经历什么

打开看见自己当前的主将与出征目标；整备时真正看见这次带谁、用什么；进入战场后，几乎不用读长说明就能瞄准红门、打出奖励并横移领取。队伍增长显著，敌人接触的位置清楚，换装能从人物和弹幕中认出。战后只展现本次实际完成的变化，再连到营地/下一关。

全局信息层级：眼前危险与可射击目标 > 己方实时兵力 > 当前奖励/火力变化 > 关卡进度 > 长期身份说明。首页的信息层级另行设置，不能把同一条战斗HUD搬到所有页面。

## 2. 一套美术语言，三种场景用途

统一方向：三国军旅的手绘小型场景。沿用蓝色识别布料、人物比例取向、武器关系和旧金/墨青配色；角色在实际尺寸下要清楚。禁止把所有页面处理成一条跑道上加几块深色按钮。

### A. 非战斗：军营/驻地展示空间
- 静止的景深背景与一个明确展示区。营门、帐篷、旗帜、桌案选少量构成空间；不循环滚动跑道，不同时出现大城门、小城门和一张地图。
- 文字背景低对比。顶端留可读区；武器/同袍区域有清楚的面板和边界。
- 首页以主将为主，整备以主将和一位随军同袍为主，驻地才展示地图/设施。每页只保留与任务有关的对象。

### B. 战斗：同一套投影下的连续道路
- 前方3组以内的关键选择应当清楚，远处环境淡化。地面承担运动感，不承担装饰主角。
- 去掉清晰的横向矩形拼接色带；路面使用少量变化的土色、车辙/踏痕和路缘，世界位置连续。
- 山道用岩岸/灌木/路侧木桩，营寨用帐篷和低木墙，城门用有限城防地标。大建筑不按等距装饰反复出现。
- 地景离开完整视口后再回收，禁止整组回跳。高对比景物不遮挡选择通道。

### C. 战后：一个人物与一次结果
- 背景为本关战场静止后的环境或独立低对比结果舞台。
- 只绘制一个主将/结果展示体，不同时保留首页人物、营地小队和晋升肖像。
- 新同袍首次加入可以短暂站到主将侧面，其后退出；重复挑战只显示本关结果，不重复招募演出。

## 3. 全部页面的目标结构

### 首页 Home
顶区：字标《一路长歌：三国》与小字号章节；不是通栏巨型牌匾。
中区：一个3/4或现有可用肖像的主将，手持所选兵器。镜头/空间以主将为中心，避免一直背对玩家且被文字隔断。旁边仅一个当前身份标记。
下区：本次目标（如“继续：夺粮立营”）及唯一强主按钮。二级入口为“行军整备”“关卡”，设置低权重置于安全位置。
状态：新玩家“出征”；未完成过渡“继续整军/建营”；中途“继续征程”；三关结束“返回白石”。必须绑定已有行为，不强制写死某个按钮文案。
完整身份链不常驻首页；移动到关卡/成长信息处。不存在的新功能不画入口。

### 关卡 Chapters
只显示真实三关。每关用一个节点卡：地点/关名、状态、最佳成绩；未解锁说明下一步条件。当前节点最明显。
原best与runnerBest不得混写。正常UI优先显示当前runner成绩，旧数据留兼容记录或既有历史入口；不能重置。

### 行军整备 Loadout
采用“标题—展示台—选择区—返回/出征”的单页任务结构。
- 标题和说明独占可读顶区，背景城楼不得穿过文字。
- 主将站在展示台一侧，当前同袍站另一侧。无队友时留出空位说明，不复制主将。
- 主将兵器：两张紧凑卡，缩略武器、名称、选中状态；可点区域至少44逻辑像素。
- 随军同袍：三张可横向排或短屏滚动的角色卡，头像/兵器标志/名字/选中状态。未解锁不伪造解锁入口。
- “主将兵器/随军同袍”和途中获得的“本局火力”分开。当前runner未提供的刀枪伤害属性，不允许用虚构面板展示；兵法已不在本轮主流程中，删掉要求选择兵法的文案。
- 保留原选择即保存的行为，底部“返回出征”；除非现有入口本来就直接出征，不新增隐藏开战副作用。
- 短屏滚动选择区域，底部动作可达；不要无限缩小字号。

### 驻地 Camp / 关间过渡 Transition
驻地可用地图或营门场景，整备页不再重复完整地图。
过渡保留用户亲手插旗/整军/驻防，以及等价按钮，不把它改成长对白。
先结算与保存，再短动画，再允许进入下一关；原本连续推进逻辑要正确恢复。
新同袍奖励与身份变化在同一过程里只发生一次。输入屏蔽范围只涵盖当前UI，不能让抬手误触“下一关”。
地图地名放在稳定留白处，旗帜/建筑不得盖字。只表达本作已有驻地，不新增天下经营。

### 会面 Meeting
一个人物主视觉或两人对话构图，一次最多一至两句，不用城门、地图、全队与头像同时叠层。保持现有跳过和完成记忆。文本由原创剧情提供，不显示“架空演绎”“开发试制说明”等破坏代入感的额外标语。

### 战斗HUD
顶端安全内容区内，只保留精简任务进度和暂停。建议基础高度约48—56逻辑像素；大型敌将出现时增加独立短血条，普通清敌数不能冒充Boss血量。
实时兵力移到队伍前侧上方，数字始终附着队形并避开门值；不再只塞进顶部“连弩·12人·赵云”的一行。
火力状态用小图标+短名称，在升级时显著变化，平时低权重。队友小标记在状态区可见，战场中仍以角色轮廓识别。
危险与损失通知最高优先，其次装备/奖励；常规教程只在首次需要时短暂出现。取消屏幕底部永久两行说明。
空白区域仍能拖动，世界标签不接收触摸，不新增可点技能按钮。

### 胜利 / 失败 / 重玩
胜利：短结果标题、一个主将、当前进度；首次实际新解锁用紧凑卡展示。
重复胜利：标题可“再次取胜”，正文按目标“粮营已清”等；不能再写“陈应加入”。
失败：原因来自最后一次真实损失，显示来源、实际损失及剩余人数；不笼统责备。
按钮只有一个强主动作，两个弱辅助：整军/下一关/回营是状态驱动；“再战本关”“返回关卡”降权。
新best、历史best、是否保存失败如实表现，不用“已保存”掩盖写入异常。

### 暂停 / 设置 / 错误态
暂停冻结战斗，背景降亮度，操作有序。设置不重建背景角色，只继承上一页的环境。
保留音效、震动、必要许可信息；BGM不请求、不播放，原许可可在致谢次级信息中保存。
加载中、失败重试、写入失败、空队友、未解锁均有短文案与可达按钮。错误提示不能落在底部手势区域之外。

## 4. 战斗表现一起升级

### 队伍
- 主将最清楚，同袍有侧前/侧后识别位置，普通兵更简洁。名字不盖身体。
- 先试主将可见高度约普通兵1.2—1.4倍、同袍约1.1—1.3倍，不沿用一律放大的方式；数值是设计候选。
- 先为主将/同袍预留不同形状占位，再排普通兵。队伍变大后依然是一团可移动的队伍，禁止扩成横贯全路的墙。
- 转向时根位置立刻响应；可允许很小的摆动，但不可让判定跟随一个不可见的原阵型。增加/损失人数时有短重新成阵。
- 1/8/24/48及256真实、48可见均有可读方案；火力权重守恒。

### 敌我接触
- 活敌走近和侧向围上来需要保留，但不能全锁在一条线里重叠。
- 使用有限接近槽位/低成本相互避让，并保留模型中实际接触；必要时调整局部追击路线。不能只移动美术身体、继续在旧位置结算。
- 最近接触者有清楚的刺/砍/推撞动作或短促受力。实际损兵在对应前沿显示一次短红闪和−N，成员退出要能看见。
- 无法从一张截图断定伤害bug。本轮先确保损失账本、接触源和屏幕反馈一致，再讨论频率。
- 切勿删活敌、让活敌穿过后算击杀、扩大保护到无敌，或取消占位风险以清爽画面。

### 数值门
- 蓝青正值、朱红负值，0以中性浅色并保留数值。符号+/-一直显示。
- 正负底色稳定；受击只亮边、抖动小数字或亮点，不能整块变金覆盖安全含义。
- 打正瞬间一次翻色和+0→+1增长反馈；经过时数值按实际兑现，领取后门退出。
- 达到当前上限时给很小的“已满”标志，避免射击半天完全没反馈；如果长期过早封顶，进入节奏校准，不能只靠标志掩盖。
- 造型为轻薄旗门/木架，阴影和足点与道路一致；不做浮空大扁牌。

### 奖励箱
- 兵员、武器、连门发生器、战地同袍必须有不同顶部图标/轮廓，统一木/金属材质与光照。
- 第一眼看懂奖励：同袍+6、连弩、赵云助阵；另一层看到剩余耐久45/220。
- 击破有短解体和图标飞入，人物并队、装备换装或链门产生各有不同结果。
- 领取、击破、尚未达到耐久不能混为一谈。击破即得的箱子不能动画飞很久才实际发奖。

### 连续+1门、隔离结构
- 保留逐个通过与逐个加人，用连续短光点/数字连跳表现；可视觉合并提示，不合并奖励事务。
- 相邻门与前后敌兵要能分层识别；过密时优先整理标牌高度与层级，再做有记录的间距调整。
- 隔离结构表现为低障碍/栅栏并有明确下方开口；其可见边界和挡弹范围一致。不做毫无体积的长褐线。

### 射击、换装与击杀
- 发射点来自实际持械手/弓口；弹道冻结、碰撞与消失均受真实状态驱动。
- 基础弩、连弩、火矢从密度、箭头/拖尾和命中反应区分，颜色只是辅助手段。
- 换装图标与队员装备/投射物在同一事件上变化。火矢爆炸只影响合同允许的对象，不为视觉增加伤害。
- 一串普通兵倒下要短而清楚，残体与灰尘迅速回收，留出下一组目标。少量武将/精英使用清楚血条，不给所有杂兵挂名字。
- 不增加全屏闪白、晃屏或长停顿。音效并发/响度限流，觉察来自短而准确的反馈。

## 5. 三关节奏整体校准

核心是“把火力投向哪一列，什么时候转向”，不得恢复划分独立难路/易路。

第一关：早期明确体验红门打正、兵员箱、换装及敌群压力。能提前看见下一组目标，避免大量时间只有跑道与静止数字。
第二关：连续+1与隔离道路是主角，射击奖励和压制敌军之间形成取舍；不能敌群堆在队伍侧面直到只能乱滑。
第三关：多列高耐久奖励、负门和大型敌将是重点；保留距离与敌将击破双条件，队友/火力足以带来可见变化。

调参顺序：先修图层/几何/标签，固定展示后观察；再检查门封顶、目标剩余可射时间、奖励后是否立刻来得及用于后续。优先每关选最影响体验的两三个事件调整，不重做三关所有数值。

允许比较最多两组参数候选，记录门值变化次数、封顶时刻、有效瞄准时间、到达前剩余耐久、错过对象、损失原因。一次自动优选路线不能证明普通玩家节奏合适。

不能用提高一切速度、把人物全部放大、把奖励暴涨或Boss降血来作为全局优化。

## 6. 这一轮的产品完成门槛

首页、整备、过渡、结果有一致的字体、间距、色彩语义和角色展示；战斗有明确的前后关系与选择；同屏人物不靠互相覆盖来塞下；可见奖励和实际成长一致；三关能够从出征连续玩到驻防。

“功能存在”与“达到了此设计”分开记录。现有测试全绿不能替代看真实页面。用户仍负责最终审美与手感判断，但执行者有责任先独立消除明显的低对比、重叠、伪动画和错误状态，不把这些留给用户一项项指出。
