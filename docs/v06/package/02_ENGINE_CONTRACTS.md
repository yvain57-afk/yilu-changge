# 接入现有工程：必须处理的模型变化

## 已读取的实现与版本
核对基线：7ee7685（v0.5.1）。真正执行始终以最新本地为准。
- core/model.ts：目前Obstacle主要用固定at，projectiles/candidates/weaponWaves围绕静态目标做交叉；rewardKill用eliteIds；newAttack给1/1/2预算；近战和波有共用账本。
- core/weapons.ts：枪near=1.1，刀near=.85，攻击周期36tick；已有准确兵器接触和队友计数。
- core/growth.ts：键yilu-changge-growth-v05，永久武器/队友与首胜奖励已存在。
- Game.ts/BattleView.ts/Volley.ts/WorldScenery.ts/Platform.ts：画面、齐射、连续投影、安全区与平台边界沿用。UI本地可能更新，不能整文件覆盖。

这轮绝不能只复制几十个Sprite；也不能仅改o.at然后保留所有静态碰撞公式。

## 1. 小范围模块建议
在现有core下面增加独立的HordeDirector、BranchDirector、Tactics（名称可顺应工程），由Journey组合；Boss在既有攻击驱动中接共享HazardGeometry。不要另写HTML游戏、改引擎或重新实现全部存档。
config是数据输入，不能把JSON直接覆盖当前levels.ts；保留id、故事、Boss身份、关间事件引用，把hordeV06配置挂到同一个稳定关卡id。

StageInfo必须暴露当前fork/route/stage/kills/tactic、活跃/排队/跳过出生数，供UI与只读snapshot使用。保留当前快照调用；诊断新增只读，不开放加兵、改血、强制胜利接口。

## 2. 两类目标共存
静态地形/数字门继续固定worldZ；动态敌兵有：
```
EnemyRuntime {
 id: string; generation: number; kind; isOrdinary;
 previousX; x; previousZ; worldZ; hp; maxHp;
 speed; radiusX; depthRadius; spawnStage; routeId;
 dead; breached; killRecorded; lastControlTick;
}
```
池槽可以复用，但id/generation每次出生要不同，否则旧波的命中账本会误挡新敌人。runId隔离每局；对象回收清理状态、事件和UI引用。

统一target adapter返回当前/上一tick位置、身体形状、材质、真实血量及稳定id。当前所有射箭、主将近战、队友近战、武器波、碰撞、血条、精锐升级显示都从adapter读，不各自猜一个位置。

## 3. 固定步长次序
一个tick建议次序：
1. 记录旧坐标；处理输入和玩家z推进；根据z一次决定fork，并收集待处理数字门，不在此步骤发门收益。
2. 应用合法出生；推进敌军位置与控制状态；推进Boss真实动作。
3. 发射快照；推进箭、主将/队友攻击与波；按实际接触先后排序处理。
4. 调用统一applyDamage；死者发一次death/kill；集成击杀升阶。
5. 活着的敌兵接触/越线，普通碰撞使用独立12tick/2损失合并器；再处理待触发数字门，门守卫必须先扣兵再增益，归零不能复活。
6. 处理敌人/Boss真实危险几何扫过队伍中心；同attackGroup最多一次伤害。
7. 尚活着才发已通过出口奖励；清理回收；更新展示事件。
遇到同tick门线与伤害，仍保留当前“箭先清障/扣兵后门收益、归零不复活”合同；若时序兼容需要微调，写一条真回归，不能降低断言。

## 4. 移动目标碰撞
以相对运动求交。箭从a0到a1、敌兵从e0到e1，应检查[a0-e0, a1-e1]是否扫过身体，不再只检查prevArrow<enemy.at && arrow>=enemy.at。
宽体波使用连续胶囊/扇形，兼顾x,z；最近的实际碰撞参数t优先，id只作为同t稳定次序。不能因数组遍历顺序穿过前面的石头打后排。
近战继续使用v0.5.1的固定武器长度、动作曲线和contactSurface；群攻只是对同一实际扫掠范围内更多敌人重复几何查询，不把near范围直接当成必中圆盘。

## 5. 共享攻击账本与预算
AttackInstance增加ordinaryBudget与specialBudget，创建时冻结；hitTargetIds仍近战/波共享。一名普通兵只能被一次攻击结算一次，控制也不重复触发。已死目标不再占后续新攻击预算。
- 普通目标吃ordinaryBudget；精锐/弩兵/可毁障碍吃specialBudget。
- Boss同attackId只接受一次，贯阵不加Boss伤害。控制不作用于Boss。
- 山石截断当前路径；木障如果命中后未破，同样截断。木障被当次打破，是否继续由当前合法预算决定，不能重新刷新账本。
- 后排弓兵原有合并投射物预算与伤害冻结继续保留；allied count = hero + (activeCompanion ? 1 : 0) + archers，不能把主将/队友重复算为弓兵。

## 6. 统一死亡出口
集中onEnemyDeath负责 killRecorded、death event、实际伤害统计、回收标志。
主将、队友、弓兵同tick最后一击只产生一次死亡。记击殺前验证敌人是可计敌兵且hp从>0变到0。物件破坏走另一条事件，不能触发击杀成长。累计上限由本局计划的真实出生数约束，重开清空集合。
使用runtime.obstacles替代旧数组时，逐一审计rewardKill、sprite name、dead列表、波retention和既有eliteIds。不要把全部普通兵错误标为精锐，也不要把它们送入旧精锐直升逻辑。

## 7. 分路细节
分路与数字门使用不同事件id和账本。BranchChoice在队伍跨线时一次冻结难度、队形、出兵和退出奖励。运行中左右移动只用于躲避，不再修改routeId。
透视展开仅是背景/地标变换，玩家真实x与世界z连续，伤害、瞄准、手指坐标不重映射。所有未选路线的敌人都不实例化，预览中的装饰不能成为可攻击目标。
入口路牌不同时显示三层操作。数字门的提交点至少比路线提交晚2秒。新阶段出生计划使用绝对id，不因为开关UI/暂停重新排时间。

## 8. 有限出生队列与终点
活跃数包含全部仍能攻击/碰撞的普通兵、精锐、弩兵。排队对象不在世界里、不显示、不攻击。生出时必须位于远端或屏幕外侧，距首次可能伤害至少1.8秒；禁止塞进玩家脚下。
延迟补生会重设合法出生位置，不能用“原计划早就到了”把怪一口气推进到近处。正常路线不应靠频繁取消计划达成性能目标；将planned/spawned/dead/breached/skipped分开报。
进入Boss前至少6秒不计划新敌人。若受震军或延迟影响还有活敌，抵达终点后仅停止地面推进，玩家继续战斗，敌军继续靠近/退出；Boss呈现入场但不同时强制发招。残余自然解决后开始Boss，不超时判负、不删怪补经验、不隐藏结束路线。
Boss HP保持当前本地已验证值作为初值；如果新路线让Boss明显拖长/秒杀，先提交按来源真实伤害记录，再做有限数值调整并留原因，不动态读玩家强弱改血。

## 9. 存档与回放
旧Book/Campaign/Growth键及已通关、解锁、最高身份不得清空。新兵法选择用独立小键yilu-changge-tactics-v06；已有同等字段时做向后兼容合并，不重复造两个槽。
schemaVersion=1，equipped仅接受guanzhen/zhenjun，非法回默认guanzhen并提示，不因此回退其他存档。两个兵法默认可用，无需迁移奖励。进局冻结runTactic。
局内路线/击杀等不永久存。现有后台暂停保持局内状态；主动重开归零并恢复当前关出征数。网页刷新沿用现有回营/重开机制，不声称支持未做的局中断点续战。
关间胜利/解锁依赖原id和现有一次性奖励；最高兵力纪录不降低。已有武器队友仍可带，同名Boss待命和N=1行为继续。

## 10. UI协作、微信、资源
新的两个兵法图标与路牌属于UI组件，不烘焙文字进PNG。既有UI agent若更新Game.ts，保留并接入；战场标签与安全区使用统一布局结果。不要为新组件移动战斗模型中心或把所有角色缩小。
战斗核心位置、发射锚点、触控坐标随设备映射一致。不得硬编码某一款手机刘海高度，微信胶囊单独避让。
根据已核对v051反馈，预览包接近其当时上限；这是历史项目记录，实际执行需检查当前工具与包体。优先复用图集、小型透明特效、简单路牌，不加入新音乐/完整字体/大量无关角色。保留源素材，只从构建产物裁剪真正不加载内容。

## 11. 旧测试的处理
新增玩法不是允许删除旧测试。区分：
继续保持：门互斥/零兵失败/存档/暂停/接触真实性/队友计数/无隐藏加伤。
按新要求明确更新：静态敌人、旧门位、精锐直升、普通兵1/1/2预算、精确旧路线通关秒数。
旧体验快照留legacy-v051夹具，新profile测试新合同。不要把所有测试切到旧profile来冒充新版验证，也不能用skip/todo隐藏失败。
