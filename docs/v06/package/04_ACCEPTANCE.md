# 小而真实的验证与一次交付

## 1. 本包已经检查什么
运行 `node tools/check_package.mjs` 与 `node --test contracts/reference.test.mjs` 可检查本包配置/纯函数。
它们没有加载Cocos、没有执行项目模型、没有验证手机、没有测玩家体验。结果在evidence。不得复制成“游戏测试通过”。

## 2. Codex需要接到真实模型的最小合同
H01 真实兵海：出生数量准确；替换快兵/弩兵计入总量；<=64活敌；复用池slot后id不同。排队未出生绝不判伤；超预算明确统计。
H02 动态命中：敌人自己迎面移动时能与箭/刀/枪碰撞；快兵不能穿过攻击；近处石头遮住后排；模型与渲染读同一位置。
H03 路线：每个fork一次选择，x=0归右；快速横移不能获取另一侧奖励；未选侧不出兵；选完后仍可全宽走位，逻辑坐标不跳；暂停回来不再发奖励。
H04 出口：只有穿越且活着才援军；同tick先归零不得复活；满兵不超256；逃离/取消出生不算击杀。
H05 群攻：枪/刀按几何分别击中多个普通兵；普通目标不受旧1/1/2截断；精锐与Boss不被贯阵刷重复伤害；近战和波共账本。
H06 成长：主将/弓兵/队友死亡出口统一，29→30、79→80阈值正确，同tick多目标只按实际死亡数；旧精锐直升不叠加；中途升级不增强已出手旧波；重开重置局内、不丢永久。
H07 兵法：贯阵只增加普通目标数量；震军不被弓兵触发、不控制Boss、不无限续控，不改玩家速度；四种组合可用。
H08 碰撞：普通敌人一生最多一次冲撞、12tick扣兵最多2；Boss/弩箭独立；实际损失不超过余兵；最后一人仍会失败。
H09 Boss几何：扇形/飞叉/枪芒与实际危险相符；双叉一组一次判伤；蓄力后不追踪；0.25秒反应延迟后有合法安全路径；收招保持短刀/近战队友可达。
H10 持续流程：3关开启、关间、原存档、已选队友/武器、同名Boss待命、奖励不重复、SFX暂停、BGM零加载继续有效。

旧测试因新产品要求而变化的，要写清是哪条变了；不删测试、不弱化断言把旧结果拼成新结论。

## 3. 轻量预算
局部模型和类型检查随改动；复用现有测试入口，不先研究新测试框架。
四种组合×三关：离线固定步长合法移动控制器短时运行，控制器不得改血/改兵/跳Boss。至少稳进与强攻两类策略，记录胜负、时间、kill、兵力、主将/弓兵/队友实际伤害。模型可快跑，不播放12遍真人速度录像。脚本表现不等于玩家通过率。
范围测试另用隔离夹具，明确标记。安全路线在低阶/无觉醒条件下必须有实际可通路径；不要求人人不动就能赢，也不要求每个极端低兵战斗强制限时。
如果弱路线Boss明显拖长，先报告入场兵力/阶级/实际DPS；基于证据有限改静态初值，记录前后，不隐藏自适应改血。

## 4. 最少画面证据
A 一段20—30秒原速片段：真实敌群连续来，至少一次分路提交、一次枪穿列/刀扫群与击殺升阶。不能拿两个静态敌人代替。
B 同一路口同种敌群两段短对照：枪＋贯阵、刀＋震军。可用显式隔离夹具固定输入/成长用于比较，画面标“搭配对照”，不冒充正常解锁。
C 每位Boss至少两招在正常大小能读懂；优先从最终流程切片。自然通关太快没覆盖第二招时，只补该Boss短夹具，不重新跑三关。
D 一次正常三关（自然时间、真实触控脚本或人均可，注明操作者），原速现场音效录像复用；统计主角/队友、升级和路由。背景音乐不出现。

## 5. 密度与手机
仅因为本轮新增动态敌人，跑一次约20秒可复现高密度夹具与三次快速重开。检查正常视口360/390、物体池/内存是否稳定、长帧、危险标签和刘海/胶囊避让。目标60FPS，达不到先减少非关键粒子、合批/复用，不能把真实敌群换回两只怪。没有真机则不宣称真机达标。
最后使用当前本地可验证的测试AppID生成一次新微信预览，先核对工具能力、登录、包体；不得用旧二维码。需扫码登录就请用户操作官方窗口。本轮不注册身份、不审核、不发布、不切游客占位。Web结果、预览成功、实际手机验收分别报告。
不默认运行旧十局、verify-v03全套、重复微信游客构建。失败只跑相关复测；最终同源指纹+简报足够，不写多份长故事。
