## 已撤下与保留

- 默认三关不再使用独立难易分路、固定倍增选门、30/80击杀升级、精锐升阶、兵法控场、三阶觉醒或强制近战Boss。旧实现与测试配置单独保留，不与新玩法混算。
- 三国角色、图集、UI设计和安全区、连续地景、暂停音效、永久解锁、关间整军/建营/驻防保持；音乐仍关闭。
- 兵器/同袍选择保留外观与出场，整备页说明本局火力从途中补给获得。
- 旧档的 best 数值不改写；新战绩保存在同一存档的独立 runnerVideoV2.best 字段，通关解锁共享且幂等。

## 明确采用的本作初值

- 起兵1/1/3；固定60Hz；48个可见成员、256人数上限、64普通敌军+1大敌将、512逻辑弹、24活跃链门。
- 各可见成员真实发射，超过48人按整数权重分配；赵云更慢的局部爆裂出手按同一成员预算缩放，没有额外全队伤害。
- 基础每0.25秒1伤害，连弩每0.2秒1伤害，火矢每0.45秒2.5伤害。门/桶只吃直接命中，爆炸只伤敌人。
- 门值增长使用附件各门 damagePerPoint。多人独立命中让原64正向上限增长过快，实测首关曾达226人，因此固定改为开局8，之后第1/2/3关分别4/12/8。不是按玩家表现动态调数。
- 门触发使用各可见成员脚底半径0.025，最多7列，宽度约0.405；每扇门独立，无每排互斥。新成员下一固定步才参与碰撞。
- 普通敌人接近队伍后追击可见脚底，1人/0.8秒，0.2秒全队受击保护；敌人不因离开镜头被记作击杀。
- 分隔结构只在前方1.5—7.5范围出现，长度连续变化并挡弹；不是原版完整物理规则的复刻。
- 第三关胜利条件是到达目的地且击败敌将，终点未打完可继续战斗，没有隐藏超时。
- 这些都是显式工程/平衡初值。原版触控、碰撞、伤害倍率、桶领取算法仍未确认，不宣称完全还原。

## 代码入口与复现

- `assets/scripts/core/runner.ts`：真实成员、发射、最近交点、门/箱/敌群/链门及状态账本。
- `assets/scripts/core/runnerConfig.ts`：附件编排与明确调参；`levels.ts` 默认接入三关。
- `BattleView.ts`、`Game.ts`：同世界投影、换装、可读的不同进度、保留 UI 安全区。
- `core/save.ts`：新战绩分栏；旧档、解锁不清空。
- `tests/runner-v08.test.ts`：新机制实际模型回归；附件参考函数自检另存，不能冒充游戏测试。
- `tools/browser-v08-delivery.mjs`：一次合法触摸连续三关；`browser-v08-fixtures.mjs`：明确隔离夹具。
- 本机启动：`PORT=43192 node tools/serve.mjs`，打开 `/play/?v=08` 和 `/review/v08/`。
- 重编译：`YILU_EVIDENCE_DIR=evidence/v08 npm run build:web`。Cocos 3.8.8，Node 18+。
- 运行浏览器脚本前：`npx tsc -p tsconfig.core.json`；`npx tsc tools/v08-policy.ts --target ES2020 --module CommonJS --outDir .cache/v08-logic --skipLibCheck`。
- 脚本使用本机Chrome路径及43192端口；历史 npm test:browser 不是本版入口。
