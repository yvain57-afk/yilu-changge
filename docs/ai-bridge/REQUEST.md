索引采用本地 JSON 或 Python 自带 SQLite；图片处理使用一个成熟的本地库；文件变更监听采用一个轻量库。不要引入 embedding 或任何模型 API。录像处理优先复用已安装的 FFmpeg；没有时根据现有 macOS/Xcode 工具使用 AVFoundation 小型命令行实现。只选一条可运行实现，不同时开发两套，也不为此下载完整视频编辑套件。

## 4. 版本、快照与自动更新

### 4.1 一份证据对应什么版本

每个快照包含：`project_id`、`snapshot_id`、带时区的采集开始/结束时间、branch、HEAD、dirty、工作内容指纹、文件清单与内容哈希、索引版本、排除项统计、资料完整性和采集状态。

HEAD 相同不意味着工作内容相同。必须将允许导出的暂存、未暂存与新增文件内容纳入工作内容指纹。Git 之外的目录也必须有内容指纹，不能伪造提交版本。

分别记录 `code_fingerprint`（实际源码、影响构建的配置和资产）与 `evidence_fingerprint`（报告、截图、日志、交接记录）。新增一份测试报告或运行 finalize 不应让未变化的代码被误判成“已改动、旧测试失效”。构建与测试绑定 code_fingerprint，完整资料快照同时保留两类指纹；两类清单与排除依据可查。

源文件、报告、图片和运行记录分别有自己的证据标识、原始时间、文件哈希与版本归属。报告至少区分 `observed_at`（被采集时间）和 `produced_at`（实际生成时间）。后者不知道就为 null；文件修改时间不能自动冒充测试时间。

图片与录像的版本关联优先使用捕获时记录的 build/run 标识或同目录清单。仅凭文件名、日期或靠近新版本不能认定它是当前画面。关联不明显示 unknown，允许用户通过本地导入时明确指定，但保留该关联来源为 user_assigned。

### 4.2 采集方式

首次做一次有范围的完整索引，随后根据白名单目录变化增量更新。源码默认停止变更五秒后合并采集；持续写入的运行日志按十至三十秒批次读取完整记录，并设最长三十秒的采集调度等待，避免每秒日志不断重置防抖计时。调度到点仍需通过一致性检查，不能为追求更新速度发布变化中的源码。读取日志仅处理确定完整的记录边界。

不重复全量扫描，不因构建目录、自己的日志和快照输出形成循环。源码变化只更新资料，不运行游戏、构建或测试。

采集期间检查文件内容和 Git 状态前后是否稳定；发生变化进行有上限的重试，仍不稳定时保留上一份完整快照并标记 updating。不把正在变动的多文件读数声称为原子工作树快照。

快照以临时目录构建并原子发布，正文从不可变副本读取；禁止使用指向仍在修改的业务文件的硬链接或软链接冒充快照。单轮分析从 overview 获取 snapshot_id，后续工具必须携带同一个 id。没有匹配的快照就报错，不能偷偷回落到 latest。

不同资料更新可以生成新快照，但要保留各自的原始版本归属。旧测试与新代码并存时，明确显示测试尚未覆盖当前工作内容。

实现手动 refresh 与开发收尾 finalize。即使监听暂时失效，用户仍有一条确定命令更新。finalize 更新本轮任务证据和快照，不重新执行测试。

默认保留最近二十个快照，并保留最近二十四小时内已经发布的快照，避免持续运行日志把同一轮长分析的基线提前回收。支持本地 pin/unpin 保护更长期审查的快照，优先回收超过上述保留窗口且未保护的旧内容。运行状态总空间默认上限 2 GiB，可配置。超限且没有安全回收对象时停止发布、返回 storage_limit，不删源材料、不破坏已保护快照。对多份快照里的相同内容去重，不每次复制全部录像。

overview 必须报告采集器状态、最近成功时间、最新快照、当前是否更新中/失败，以及报告时间。采集器心跳丢失不能只靠“文件还在”显示服务健康。

## 5. 图片、录像与用户反馈

### 5.1 图片必须真的可看

实现 MCP 标准 ImageContent，读取经授权的图片并返回像素、尺寸、证据来源、捕获类型和版本关联。只返回本机路径、Markdown 图片地址、base64 文本或文件名，不算完成图片读取。

默认按需返回长边不超过 1600 像素的预览。检查字体、细节和遮挡时，支持受限的原图或裁剪；单次最多四张、总返回量有上限。预览不得修图、补字、重绘或改变比例，不覆盖源资产。透明素材保留透明信息。

MCP 协议支持图片结果；特定 ChatGPT 客户端和模型是否实际取得图片，要通过账号端到端验收。[S7]客户端只显示文字时登记为明确的功能阻断，不能把“本地返回了 base64”写成“ChatGPT 已看图”。禁止为绕过这一点自动开启匿名公网图床。

图片仅取自项目资产、证据白名单及用户主动导入的文件；不读取整机截图目录、照片图库或整个下载目录。去除不必要 EXIF。文字密钥扫描不能证明截图没有敏感内容，导入入口必须提示仅选游戏相关画面。

### 5.2 录像通过真实关键帧提供

本轮实现 MP4/MOV 的本地导入、时长/尺寸/帧率元数据、带原视频时间戳的关键帧，以及指定时间段的较密帧导出。默认首次导入最多十二张概览帧；局部细看通过本地命令提取指定区间，单次最多三十张，使用缓存避免重复解码。MCP 只读这些已生成的帧，可分页获取。

关键帧须保留视频证据 id、时间戳、原始时长及转换参数。参考游戏录像、自然试玩、固定夹具、原速/加速录像分别标记。未知属性不能猜。关键帧能帮助定位画面问题，不能当作完整视频播放、音效审查或帧率测量。

不尝试让只读 MCP 远程启动录屏、不开发视频流直播、不为了凑证据重新录制全部关卡。需要验证动作连续性或音效时，使用原速原文件与实测记录，并明确工具的观察边界。

### 5.3 手机材料的入口

复用当前工程的截图和录像归档目录；另外提供一个只接收用户选择文件的本地导入入口。手机截图、录像或诊断文件由用户主动传到 Mac/导出后导入，随后自动索引。不得宣称可以无授权地读取手机相册或已安装应用的私有目录。

已有用户反馈可引用其实际来源；新增反馈只需简短 Markdown，记录问题、所在页面/关卡、关联 evidence_id、确认状态。不要另做工单网站。

## 6. 《一路长歌》开发态运行诊断

先接已有日志与性能记录。若当前工程缺少可用数据，本轮补一个轻量的开发态诊断适配，输出本地 JSONL，不建设遥测平台，不发送第三方网络请求。

需要覆盖的基础事件：启动、页面/场景进入、关卡开始/结束、可捕获的业务错误。每次运行生成 run_id，关联真实 build 标识、设备类别、平台、构建类型、视口与安全区。构建前记录源码内容指纹，不能用应用启动当天的最新 HEAD 反填旧构建。

对能在现有引擎中直接取到的项目做低开销采样：帧间隔分布、长帧统计、逻辑兵力、实际可见我军数、当前显示上限、活动敌军数、可见敌军数、活动投射物数。区分逻辑实体数量与渲染数量；不能因为界面上只画八人就推断实际只有八人。

帧数据在内存中聚合，每秒或适当批次落盘；不要每帧写文件。明确帧间隔、CPU/GPU 渲染耗时的差异，不能以定时器间隔冒充 GPU 耗时。无法可靠获取的 draw call、内存或 GPU 指标标 unavailable，不为补全指标大改渲染器。

诊断代码由开发构建开关保护，发布构建默认关闭；不影响存档、碰撞、数值、控制手感和正式 UI。处理日志容量上限、缓冲、退出清理，不因采集失败导致游戏崩溃。

iOS 依照现有工程实现本地导出：模拟器由本地工具读取已经确认的应用容器导出件；真机复用现有开发导出方式，没有时增加仅在开发设置可见的“导出诊断”操作。用户主动导出后进入资料采集目录，不自动开放局域网服务器、不扫描整个设备。

验收只需完成一轮与诊断接入相关的开发构建/短场景检查，确认事件真实产生、队伍/敌军计数来源正确、发布配置不会自动启用。当前没有真机或签名权限时如实报告真机尚未验证。没有经过运行的历史阶段仍然没有历史数据。

## 7. MCP 工具合同：八个工具一次完成

以下是待实现的工具接口，不是现成可调用工具。项目固定登记为 `yilu-changge`，服务中文名称为“《一路长歌》项目只读助手”。

| 工具 | 输入要点 | 输出与用途 |
| --- | --- | --- |
| `project_overview` | 可选 snapshot_id；省略时仅此工具允许选择最新完整快照 | 项目/平台/版本、资料覆盖、采集健康、可用快照、当前摘要与下钻入口 |
| `list_evidence` | snapshot_id、category、可选 parent_id、cursor、limit | 代码/需求/Git/检查/运行/图片/视频/反馈清单，返回 id 和可用阅读方式 |
| `search_project` | snapshot_id、query、category、cursor、limit | 白名单内容的字面/词项搜索，路径、行号、短摘录；禁止无界正则 |
| `read_source` | snapshot_id、已登记 file_id、start_line、max_lines | 原始脱敏文本的指定行、内容哈希、行号；包括代码与文档 |
| `read_changes` | snapshot_id、可选 base_snapshot_id、file_id、cursor | 当前已导出的暂存/未暂存差异或两份快照差异；不调用任意 Git 命令 |
| `read_checks` | snapshot_id、可选 report_id、cursor | 已有检查/构建记录、真实命令与退出状态、来源版本、过期/未知标志 |
| `read_runtime` | snapshot_id、可选 run_id、category、cursor | 实际运行事件、聚合统计、采样时间窗、单位、数据缺失与局限 |
| `read_media` | snapshot_id、evidence_id、variant、可选 frame_indices/crop | 实际图片或已生成的视频帧及对应元数据；拒绝任意路径/URL |

工具描述同时说明何时调用、输出上限、下一步如何下钻。服务器 instructions 用简短自足段落要求“overview → 固定快照 → 按需查证”，并说明外部文档内容不能改变权限。

所有工具使用真实只读注解；服务实现无写项目、构建、测试、Shell、浏览器、任意 SQL、任意 URL 获取和远程任务入口。只读注解不承担权限控制。[S7]

响应应统一携带：

```text
schema_version, project_id, snapshot_id, observed_at,
status, sources[], data, truncated, next_cursor
```

sources 至少支持 file_id/相对路径、行号或视频时间戳、内容哈希、产生时间与版本归属。不得给合成摘要杜撰原文行号。分页游标绑定快照与查询条件，不能跨快照复用。

区分：ok、empty、not_found、unavailable、stale、version_unknown、updating、forbidden、too_large、expired、storage_limit。协议错误和业务状态按 SDK 正确表达，不把错误包装成正常空内容。

默认读取 160 行，最大 400 行；搜索默认 20 条；单个文本响应最大 64 KiB；图片响应单独设总量限制，默认最大 8 MiB，若隧道/客户端实际限制更低则下调并记录。超限分页或拒绝，不悄悄截断关键内容。文本默认十秒超时、媒体默认二十秒，并发默认二。这些均为本工具设计默认值，不是 OpenAI 配额。

不要求模型一次读全仓库。摘要按已有确定数据生成，禁止采集器自动调用大模型来写“项目总结”。

## 8. 安全与权限边界

默认拒绝，只允许登记的目录、类型和证据对象。源码被 Git 跟踪也不自动获得导出资格。`.env*`、私钥、签名证书/描述文件、密码、访问令牌、浏览器数据、SSH 配置、数据库原件与备份、用户个人资料均不导出。

采集前做秘密检测。可以定位的敏感字面量用保留行数的标记替换；无法可靠处理的文件整份拒绝并记录安全原因。差异、提交说明、构建命令、运行日志也要脱敏；不能只扫描源文件。摘要、搜索结果与错误消息不得绕过过滤。

拒绝绝对路径、路径穿越、符号链接越界、未登记子模块和文件替换竞态。file_id 和 snapshot_id 都是对象标识，不是权限凭证；每次调用核验它属于当前获准项目。读取固定快照，禁止通过文件名触发执行或反序列化不可信对象。

采集器使用固定参数的本地只读 Git 操作，禁用外部 diff/textconv 和可能执行辅助程序的配置；不采用 shell 拼接。远程工具不运行这些采集命令。当前用户同权限进程的完全隔离不在这套轻量工具保证内，说明中不要声称达到系统级沙箱隔离。

默认用 stdio 接官方隧道，避免业务 MCP 的额外网络监听。隧道管理界面如存在，应只监听本机。仅绑定用户本人要使用的 Platform organization / ChatGPT workspace，不扩展到不相关工作区。验证实际授权路径，不以拿到 tunnel_id 当成身份认证。

运行密钥由用户在本机安全输入，优先存用户 Keychain；不能打印到对话、命令历史、日志、plist、Git 或快照。隧道进程与数据服务所需环境分离，MCP 子进程不继承不需要的控制面密钥。禁止读取其他工具的现有凭据来“复用登录”。

审计记录时间、工具、项目、快照、对象/参数摘要、状态、耗时、返回大小，不记录正文或秘密。日志轮转。远程服务仅可写自己的必要审计/运行日志，不可修改业务资料和已发布快照。

停止服务与撤销隧道可以阻止后续访问；已经返回聊天的内容不会因此从聊天中自动删除。关闭训练使用同样不意味着数据完全留在本机。交付说明必须表达这一点。

## 9. 官方隧道与日常运维

使用 OpenAI Secure MCP Tunnel，优先以 stdio 连接本地服务。实施时核对官方文档、实际已安装版本与 `tunnel-client help quickstart`，再生成真实启动配置，不猜下载地址、参数或控制台按钮。

需要用户完成的账号侧动作一次集中列明：打开开发者模式；在本人 Platform 创建/选择隧道并关联目标 ChatGPT workspace；设置必要的 Read/Manage/Use 权限；本机填写运行密钥；在 ChatGPT 创建并启用连接。不要自动购买 API 点数或把规划请求改成 API 调用。[S1][S2]

官方隧道的运行密钥用于隧道控制面，本工具不得调用 Responses API 或其他模型接口。不要承诺隧道永久免费；出现额外付费或超出当前授权的账户要求先明确指出。

通过隧道与个人工作区限制满足当前私有使用需求时，不额外开发飞书登录或自建 OAuth。确实存在额外认证要求时复用受支持方式，不能临时手写残缺认证，也不能用匿名公网绕过。

在实际界面支持的情况下，路径为 Settings → Security and login → Developer mode；Plugins → 新增连接 → Tunnel。界面名称可能变化，以当前账号为准。首要验收端是桌面浏览器；不要自动承诺手机 App 能调用自建 MCP。[S2][S3]

提供统一的项目本地入口，例如 `./tools/project-reader/yilu-bridge`。以下子命令由你实现并在交付时给出可复制的真实命令；本文件不是声称这些命令现在已经存在。

```text
install / start / stop / status / doctor
refresh / pin / unpin
import-media / export-frames
capture-check / finalize
export-review
uninstall
```

`capture-check` 仅供本地用户/Codex 显式运行已选检查，记录参数、开始结束时间、退出码与源码指纹；不向远程工具暴露。参数采用 argv，避免 shell 拼接。`export-review` 导出同样经过脱敏、限量的资料包，用于账号连接故障时人工复核；它不能代替 MCP 的真实连通验收。

实现用户级 LaunchAgent 或当前环境已有的等效方式，让资料监听和隧道在登录后恢复。只配置本工具，安装可重复、失败有退避、停止能结束子进程；不修改系统级 daemon、休眠策略、路由器、VPN、防火墙或其他项目服务。无 root/sudo 需求。

status/doctor 分别显示：项目身份、采集器、快照新鲜度、MCP 本地读取、隧道运行、账号关联待检查项、图片支持验收状态。不能把某一项绿色当成整体完成。

睡眠、关机、断网时服务可能不可用；恢复后重新连接并更新。不要为了宣称全天可用永久唤醒笔记本。用户以后迁移 Mac mini 属于独立选择，本轮不迁移。

uninstall 停止服务并移除本工具的启动项；清理缓存必须限定专有目录，不删除游戏源码、既有证据或用户媒体。撤销工作区关联、删除 ChatGPT 连接、吊销运行密钥的实际步骤写入 RUNBOOK。

## 10. ChatGPT 与 Codex 的交接

### 10.1 固定摘要与项目规则

在 `docs/ai-bridge/` 内维护简短的 `CURRENT.md`，记录当前活动平台、真实构建入口、本轮任务、已确认约束、证据入口与已知缺失。正文目标不超过约 150 行，详情链接到既有文件，不复制全部历史记录。

适用 `AGENTS.md` 只追加一个短的工作流段落，不覆盖原规则：接到 ChatGPT 任务书后先比较其基线与当前工作内容；不要无目的重新全仓研究；按任务范围执行；完成后更新实际结果并 finalize。明确这属于 Codex 的项目操作约定，不是“ChatGPT 能自动调用本地 Skill”。

### 10.2 任务书内容

ChatGPT 的每份执行任务书应包含：

```text
任务 id / 目标 / project_id
baseline_snapshot_id / HEAD / code_fingerprint / evidence_fingerprint
本轮全部相关问题与证据：文件行号、截图 id、视频时间戳或运行 id
具体改动、涉及模块、依赖顺序、验收方法
已确认约束 / 不做事项 / 风险与回滚
```

用户在支持的桌面界面使用“添加到 Codex”或对应入口，或直接将最终任务书交给当前 Codex。官方资料说明 Quick chat 是普通 ChatGPT 对话，已有对话可加入 Codex；实际界面不可用时采用文件/文本交接。[S4]

只读 MCP 不向仓库写任务、不自动启动 Codex，也不自动观察用户全部聊天。禁止浏览器脚本批量提问、读取 ChatGPT Cookie/会话令牌、反代会员额度或调用非公开接口做自动交接。

### 10.3 实施与复核

Codex 检查目标、基线、相关文件与用户未提交改动。版本前进时先对比受影响部分，不为套用任务书回滚。合理的局部实现差异自行处理，涉及重大范围或损坏风险才交用户决定。

实施结束写一份短结果：每项任务 done/partial/blocked、实际变化、验证命令与结果、证据 id、新增缺失与需要用户真机确认的事项。尽量复用现有结果记录，不另堆长报告。

finalize 只记录已发生的事实并更新快照。新对话由 ChatGPT 读取新快照，对照原任务书复核；没有触发明确新目标时不重新提出一整轮无关优化。

本方案不承诺固定节省比例。普通 Chat 的用量与 Work/Codex 分开，但 MCP 搭建和 Codex 实施本身仍会消耗对应开发用量；选择模式时按账号当前显示核对。[S5]

## 11. 一次集中验收：每项保留实际证据

不要以“大量测试数量”代替完成度。用小型合成夹具验证安全与协议，再用《一路长歌》真实资料完成端到端读取。修复后只回归受影响项；安全边界变化要重跑安全组。只有诊断适配改到游戏代码时，增加必要构建与短场景验证，不默认跑十关长测。

| 项目 | 必须看到的证据 |
| --- | --- |
| 项目绑定 | 真实根目录、活动 target、Git/内容指纹与本地一致；不会读到其他项目 |
| 代码读取 | ChatGPT 返回一个真实源文件的指定行，并对应内容哈希 |
| 未提交内容 | 合成夹具中未提交改动可见；真实项目 dirty 状态正确，不为测试改业务代码 |
| 自动更新 | 合成变更引起一次合并更新，源码快照变化；旧快照仍读旧内容 |
| 一致性 | 采集时变化、过期快照、错误游标不会静默拼接新旧内容 |
| 检查记录 | 新快照中的旧测试仍显示旧时间/旧指纹；缺失结果不会显示通过 |
| 图片通道 | ChatGPT 实际辨认一张已知测试图的视觉特征，再读取一张真实游戏画面；答案不能预写在文件名中 |
| 视频通道 | 从短视频导出带正确时间戳的帧，并在 ChatGPT 中读取；注明关键帧的观察边界 |
| 运行诊断 | 一次真实开发运行产生日志，已有数据与缺失指标可区分；发布默认关闭 |
| 安全 | 越界路径、符号链接、秘密样本、未登记对象、大输入、错误快照均被正确处理；无远程执行工具 |
| 隧道与权限 | 本地服务、隧道、ChatGPT 工具扫描、真实调用逐层有证据；用户不应授权的工作区未关联 |
| 运维与交接 | 停止/恢复、状态诊断、finalize 和撤销说明可用；一份小型分析任务书可交给 Codex 正确核验基线 |

图片功能尤其要区分：服务端返回 ImageContent、本地客户端解码成功、ChatGPT 真正拿到像素。这是三层证据，不能相互代替。

账号侧无法操作的步骤单列 blocked_user_action，并提供一个合并的操作说明。开发者模式或隧道权限不可用属于外部阻断，不能靠不断换库或重复模型请求解决。没有完成真实 ChatGPT 调用之前，不得写“整体接通”。
