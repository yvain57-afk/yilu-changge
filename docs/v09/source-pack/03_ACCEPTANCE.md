# v0.9 连续交付与验收

## 1. 内部执行顺序，用户只集中看一次

### G1：共用基础和版面
核对本地最新工作区→确定页面显示所有权→整理safe rect→盘点资源。把首页、整备、战斗核心组件接进真实Cocos。

### G2：全部页面连成一套
扩展关卡、营地、过渡、会面、暂停/设置、胜利/失败。改正重复人物和错误奖励文案，处理空态与重玩态。保留已有按钮语义和存档结果。

### G3：全部三关的战场观感
调整特殊角色站位、敌我接触、足点/出弹点、队伍人数badge、门箱语义、连续+1、换装反馈和地景。三个场景共享标准，各有自己的地标。

### G4：节奏、移动端和交付
有证据地进行有限调参；同步小屏适配和资源体积；相关检查后一次自然三关兼录像，当前测试预览生成。保留所有原始反馈和未验证边界。

G1—G4是同一个工作批次。除付费、权限、素材使用权和无法独立解决的真实阻塞外，不逐项等用户批准。缺一个新图时继续其余工作，不把整批冻结；完成报告不得把临时占位冒称正式达标。

## 2. 必须覆盖的状态

详见review_states.json。用只读/隔离夹具直接打开页面，避免为了检查一个按钮每次打三关。夹具不得改变正式玩家存档，必须标注“测试状态”，不能用于伪造正常通关录像。

- 新玩家首页；老存档中途；存在未完成过渡；三关完成。
- 整备无队友、一个队友、三个解锁且选中陈应；长枪/长刀两个显示。
- 正常战斗：1/8/24/48显示人数，左右极限和居中；256真实/48可见权重另用一次密度夹具。
- 正门、负门、−1→0→+1、门封顶、红门边缘减员、箱耐久/奖励、连续+1、武器升级、大型敌将。
- 首次胜利与新招募；重复胜利无新招募；失败；保存失败；暂停返回；加载失败重试。
- 三种已存在过渡、白石驻地、赵云会面与重入。

## 4. 必须保留的机制合同

- 正负门累积伤害改值、余数与上限处理、按真实成员触碰领取。
- 同一门/箱/链门只奖励一次；同一步归零后不由后续正门复活；新增成员生效顺序不回退。
- 独立发射位置、发射后快照不随转向变化、最近对象和遮挡、高人数权重守恒。
- 火矢爆炸不重复伤主目标，不越权改门/箱数值。
- 连续+1按真实接触逐个发放，漏过不补；池上限触发的延后必须可记录且不丢目标。
- 活敌未死不能算击杀；前两关清剿条件、第三关距离加敌将条件不变。
- 主将/队友/士兵同屏人数包含关系不变，同名待命/战地赵云不覆盖永久选择。
- 稳定关卡ID、旧best与runnerBest、武器/队友解锁、当前选择、过渡记录与设置保留。
- 后台暂停、显式恢复、触摸取消、资源失败重试/保存失败仍可玩。

这些对改动相关项进行复验，不要求无关的所有旧原型测试都适用，也不允许删除适用回归来制造全绿。

## 5. 最小而完整的验证集合

1. **相关静态/逻辑检查一次**：类型、runner及进度/存档、屏幕viewModel、几何变化影响的接触/射击。按实际变更补用例。
2. **页面状态快照**：直接用隔离状态矩阵检查；UI快照可在同一浏览器会话完成，不反复走战斗。
3. **一段15—25秒压力片段＋三次快速重开**：只因这批改变阵型/特效/资源，需要检查上限与缓存。相同状态、相同池统计，不把首次缓存创建当泄漏也不能掩盖增长。
4. **最终一次自然三关**：合法输入，无加速、无篡改人数/HP/装备；同时录原速现场音效、状态变更和关键账本。可裁短片，但不另跑三遍拼成“连续”。
5. **当前本地微信测试预览**：构建/打包/二维码只证明预览生成；设备实际通过由真实手机观察后记录。要扫码由用户操作官方窗口，不恢复游客身份。

仅当失败影响更大范围、修改底层后相关旧结论失效、或用户明确要求时追加测试。日志存本地，模型只读摘要和失败上下文；不默认tools/verify-v03.mjs，不重复下载Last War视频，不为截图把全库重新喂入每个agent。

性能期望：目标机稳定接近60FPS是方向，实测设备持续低于30FPS应修复；单次平均值不能遮盖跳帧。记录p95/p99帧间隔、>33ms帧数、活跃对象/池/纹理变化。桌面结果单独标注，不作为手机结论。

## 6. 验收文件与交付内容

- 当前可玩构建和经过实际验证的本机启动方式；本地地址不伪装为公网链接。
- 首页/整备/普通战斗/接触受压/结算/驻地六组前后对照，匹配视口和状态；其他页面状态用一张矩阵辅助。
- 一次三关原速有声录像；另导出不超过45秒的亮点片段，全部从同一录像裁出。
- 1页CHANGELOG：实际改了什么、哪些未改、已验证平台、必须由用户亲验的事项。
- `ASSET_BUDGET.json`：新增/移除构建资源、压缩前后与余量、所用平台阈值来源；不公开AppID和QR。
- `VERIFICATION.json`：命令、退出状态、对应源码/构建指纹、设备/视口、自然/夹具区别，未验项不得写通过。
- `PARAMETER_DIFF.json`：本轮若调参，列旧值、新值、目的、使用场景与比较结果。没有调参则空数组。
- 若有设计源文件、图集和token，随工程保存；绝不能只给一张无法还原的概念海报。

最终对话只贴入口、6—10行变化、真实未完成条件。用户看到整体游戏变化后再集中提反馈。
