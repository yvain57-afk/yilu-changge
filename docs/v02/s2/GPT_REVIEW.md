## 实际实现

1. 山石标签从真实 `loss` 生成“山石 · 碰撞 −N”。不足人数时仍反馈实际损失。石头挡箭、不可毁规则不变。
2. Boss `.42` 半宽、深度 `4` 集中为只读 `BOSS_TARGET`，规则与渲染共用。草模前方可见受击护板覆盖完整投影宽度 161.616 设计单位。`?debug=hitboxes` 只显示边界与弹道，没有改人数/HP/时间的控制台入口。
3. 规则事件新增只读目标、深度、固定步编号、箭编号及来源。命中、击破和射击姿态读取事件；渲染不结算伤害。与冻结 S1 源逐帧对比三关各三种输入轨迹，结果完全一致。
4. 地面危险带在独立底层，门、障碍、Boss 和队伍按脚底纵向位置绘制；门值固定 44 设计字号，360/390 宽分别约 22/23.8 CSS px，不用 SHRINK。
5. 一名候选主角的真 alpha 背向分层 rig，共用头/发型/弓/四肢，通过躯干与旗切换布衣/头领。六姿态 0.76 秒步态，四姿态射击；实际战斗按 shot 事件驱动，不额外产生逻辑箭。
6. 边缘阵型按整排平移，保持 48 单位列间距，修复多个单位被逐个夹到同一横坐标。主角真实中心及所有规则数值不变。

另修复暂停后一次性音效可能继续播放的问题，改成 5 个有主、可停止的音效通道；真实输出静音检查见 `sound-pause.json`。

第一关的友军、敌人、Boss、道路仍是草模。预览中的 8/24/48/256 是**隔离的重复主角排布夹具**；显示上限 48 包含唯一队首主角；顶部另有放大的动作观察样本，不能把它计入玩法人数或把夹具截图称作正常 48 人实玩。

验证摘要：43 项测试通过；桌面连续首关 10/10，均 88 人；平均 55.23–60 FPS。5 个固定音效通道暂停后 RMS=0；合并绘制后 GPU 缓冲由 153.04 降至 49.53 MiB。微信仅游客构建；角色设计方向已认可，游戏呈现未通过。
