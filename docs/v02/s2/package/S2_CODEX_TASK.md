## 0．本轮到底做什么

只把第一关「拉起队伍」从功能草模推进到角色、场景、动作、反馈都可审查的正式试制样板。先制作一名主角的可用候选，再由用户确认角色方向，然后扩展第一关。第二、第三关仍只保留配置与规则验证，不开放实机入口。

## 3．先处理的可读性与判定对齐

### 3.1 山石必须显示损失人数

当前 BattleView.ts 对山石显示「山石 · 绕行」，没有显示配置中的loss。改为「山石 · 绕行 / 碰撞 −6」一类从配置生成的短提示。不可射毁、碰撞损失、真实生效范围都要看得见；数值不得写死。

保留山石不可射毁与挡箭规则。新增界面检查：读取关内每块山石的loss，确认显示与配置一致；低人数受到伤害时，事件反馈仍显示实际损失。

### 3.2 先对齐Boss可命中区域，再定美术尺寸

model.ts 当前Boss命中条件为 |arrow.x| ≤ 0.42，深度d=4；project缩放为0.74。对应投影命中宽度约161.6个设计单位。BattleView.ts 当前actor基础宽度115×0.74≈85.1，外轮廓考虑手臂/长矛也约百余单位。这里是静态代码对照，不是截图测量。

在同一坐标变换下显示开发用命中范围、可见主体轮廓、投射路径。以x=0、±0.41、±0.43和正常移动路线分别检查。正式Boss轮廓或明确可见的受击目标应解释有效宽度，不能让大量空白区域也算打中。

先保持现有0.42规则常量，将可命中范围暴露成只读数据供渲染使用，避免在两处复制数字。需要缩小或扩大规则命中区时，单列玩法变更，重新跑全部路线；不得作为美术小修悄悄提交。普通敌兵也做同样的轮廓与碰撞核对。

开发叠加层只能查看，不提供全局改兵力、改血、跳时间或强制胜利接口。

### 3.3 补足表现事件信息，不让渲染猜测目标

当前Feedback主要只有kind/x/amount，不足以可靠定位同通道前后目标的命中、破坏位置；Game.update把hit事件合并成播放声音。

以最小改动增加可选的只读表现元数据，例如targetId、worldZ、simulationTick、projectileId、sourceId。具体类型与当前实现保持一致，不要求照抄字段名。命中、击破、出手等时刻由规则状态或规则事件提供，渲染不得自行扣HP、重复出箭或按动画帧决定胜负。

改动前后，用同一关卡、同一固定步长输入序列比较人数、位置、箭伤害、门结算、BossHP、结束时刻。允许增加表现信息，不允许改变结果。

### 3.4 预告与遮挡

危险范围应来自Warning的真实x/width/stage，判定针对队伍中心，不能让友军装饰动画触发伤害。人物脚底的中心标记须清晰但不抢眼。

远近对象统一按地面位置安排遮挡，地面提示单独分层。不能仅按“先画所有门，再画所有障碍”的对象类型顺序覆盖画面。

危险预告不要把主角、门值和敌人全部刷成一块同色长条。保留准确地面边界，以局部透明色、收束线或轮廓表现；色弱时仍能靠形状辨认。投矛蓄力、出手、飞行、命中与恢复必须服从模型当前时序。

## 4．主角与素材规范

### 候选角色的实际设计目标

成年小人物的敏捷与向上成长感。主角通过发型、肩背轮廓、弓和一处短色带识别；避免依靠小屏看不清的面部细节。布衣衣着简洁；头领加短护甲和小旗/腰部部件，脸与体型不改变。长披风与复杂铠甲暂缓。

不用真实历史人物肖像，不先声称服装是某朝代复原。国风可以通过剪裁、轮廓、木与布的材料语言体现；避免把整屏统一染旧黄。

战斗必须使用朝前进方向的背向/侧背姿态。正面图用于参考、首页或晋升，不把正面立绘缩小后向上平移当成战斗动作。

### 最小交付资产

- 一个主角：布衣、头领两个外观，面容与比例一致。
- 一种普通友军弓手：能与主角区分，少量部件差异即可。
- 一个普通敌兵：轮廓/姿态/武器与友军区分，不能仅换红蓝。
- 投矛头目：肩背更宽，短矛清楚，动作有可读的蓄力和恢复。
- 箭、矛、命中碎屑、木障碎片、队旗和必要UI部件。

### 文件合同

正式文件放入独立v2源目录与运行目录，例如 art-source/v2/、assets/resources/v2/。具体目录由执行端结合现有工程确认，记录映射。保留原资产与.meta引用，禁止旧npm run art覆盖新素材。

透明PNG必须有真实alpha；棋盘格、米色底、白边不允许混入图像。不要靠大范围按颜色抠图误删皮肤、弓弦或衣摆。独立显示阴影；脚底锚点、大小和边距一致。每个动作禁止角色尺寸漂移、脸变形、武器左右手乱跳。

保存可编辑源、工具与提示词、修订记录和素材状态。素材清单记录source、candidate/approved、像素尺寸、逻辑尺寸、脚底pivot、动作时长、批准记录；approved不得自动置true。

生成图先确定角色与关键姿态，再拆分整理成可用素材。不要把整张概念图切几块后直接宣布完成正式资产，也不要依赖一次生成长sprite sheet来保证跨帧一致性。

## 5．动作先做“真的在走和射”

建议默认使用分层Sprite配合Cocos内置动画/时间轴，少量关键姿态切换修正弓臂。没有必要为这一轮引入付费动画软件或新的大型运行库。

跑步分为腿部步态、身体重心与上身持弓。持弓手有固定握点，拉弦手有明确后拉与释放。弓不能像挂件在人物旁边单独浮动，跑动也不能只有整张图上下晃。

先试6个步态关键姿态、约0.65—0.85秒循环；射击上身使用4个关键姿态覆盖模型0.25秒一次的节奏。关键姿态可以通过分层关键帧实现，不要求导出大量帧图。以上只是试制起点，不是改写规则时序的许可。

主角与友军的装饰步态可以错相。真实逻辑箭仍每0.25秒发射，冻结发射时人数与通道；装饰箭束不能产生额外伤害、遮住落点或暗示邻道也被清掉。

投矛头目的单次1.4秒预告，在当前模型中包含最后约0.2秒飞行。动作必须与charge→flight→impact一致；不能额外延后出手或命中。暂停/后台后，角色、地面预告、箭和音效都保持相同暂停语义。

## 6．只打磨六种关键反馈

|事件|本轮要看到/听到的变化|不能改变的东西|
|---|---|---|
|增兵|人数立即更新；新成员在约0.18—0.32秒内并入；一次短音效，队形明显展开|门一次事务、真实人数与上限、中心位置|

当前录像没有音轨，不能据此判定音效已达标。下一次提供真实游戏音轨；无法捕获时提供独立试听与实机操作记录并明确缺项，不能另配音乐冒充实机音效。

## 7．山道与界面

### 场景

先用一个开阔山口到寨门的小场景。远景有山势和寨门，中景道路和路边低矮物，近景少量树干/旗杆经过。中央为判断留白，材质细节放在两側。

近中远景各自移动或切换，但到达门线与碰撞位置必须使用统一投影。沿用真实道路中心，不能为了弯路画面把角色显示在另一个通道。初始直接让玩家看见远处目的地，Boss前让寨门逐渐清楚，不额外增加剧情或停顿。

### 屏幕信息

顶部主要保留兵力、进度与暂停。章节名与试玩标识轻量显示。首进引导随真实拖动收起；底部不恢复旧版常驻大说明板。

增兵反馈靠近队伍但不遮挡中心；门值是门上的第一视觉层。远景可淡化，但进入可决策窗口后，360/390 CSS宽视口中的运算符与数值以约20—24 CSS px为试制可读目标。避免Label.Overflow.SHRINK在未知情况下把关键数值缩成细字。

普通玩家界面收起“选定角色后制作”等开发解释；开发状态放入独立的试制标识或评审页。未开放关卡仍明确，不新增可点击空入口。

首页突出同一个主角和“从小人物起步，一步步当皇帝”，一键开始第一关。结果页保留胜利场景和晋升动作，不用大段文字替代外观变化。不要在没有读取权限时删掉存储失败、坏档或平台限制提示。
