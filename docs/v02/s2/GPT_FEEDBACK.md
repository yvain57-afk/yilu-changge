# 给 GPT 的下一轮优化反馈

2026-09-20，针对当前本地 S2-A。请先读本文件，再读 [实现与验证](GPT_REVIEW.md)。

## 用户最新判断

> 你做的这个角色，我觉得没问题啊。但我实际看你测试的页面里，那个小人太丑了。你现在测试完了这一版，有什么要反馈给GPT的吗？我要让它继续优化的。

**角色设计方向已认可；游戏里的小人及队伍呈现未通过。** 不要再要求用户重选旧 A/B，不要推翻已认可的主角身份；也不能把这句话登记为整套美术、小屏辨识度或动作验收通过。

## 当前画面为什么差

1. **实际战斗只有队首使用新角色。** 后排友军、敌兵与 Boss 仍由 `BattleView.actor()` 用圆、线、矩形绘制。新主角与旧蓝色小兵的比例、细节和风格明显不一致。见 [360 宽首关实景](../../../evidence/v02-s2/battle-360.png)。
2. **重复主角预览也不好看。** [390 宽 48 人预览](../../../evidence/v02-s2/formation-390-48-1.png) 是排布测试夹具，不是正式友军。每人都有复杂弓、衣纹和轮廓，缩小后行间遮挡，画面变成密集的重复细线。修好了左右边缘挤叠，不等于阵型观感合格。
3. **放大图好看，没有转化为游戏尺寸的清晰形象。** 主角实际高度约 47–51 CSS px，细碎纹理与细弓弦很难保留。需要专门调整轮廓、色块、武器粗细与动作幅度，不能只把大图缩小。
4. **场景和 Boss 仍是占位画面。** [Boss 实景](../../../evidence/v02-s2/boss-hit-debug.png) 的红色矩形护板用于对应命中范围，不是最终设计；道路、树、门也没有与主角统一。图中的青线为调试线，不是正式 UI。

以上是结合代码和实际截图得到的诊断；用户没有逐项指定这些原因，不能把诊断冒充用户原话。

## 请据此给出下一开发包

### 第一优先：让真实游戏里的队伍好看

- 保留已认可的主角身份、服装方向及布衣到头领关系，制作适合实际尺寸的表现：减少碎纹理，强化头肩、躯干、腿和弓的轮廓；用有限的大色块区分衣服、皮肤和装备。
- 制作一种同风格的普通友军，接入实际首关。普通友军应比主角简洁，能一眼区分主角与士兵，不能把同一主角复制 48 次当作完成。
- 调整队伍行列间距、错位、遮挡与脚底阴影，在可用屏幕空间中比较效果；增加适度步态相位差，避免整齐复印和机械堆叠。调整显示位置时保持真实移动中心和碰撞规则一致。
- 先交付真实 Cocos 首关中「主角 + 正式友军」的 8/24/48 人效果，再铺开敌兵、Boss 和场景。这是下一批交付顺序，不是再次要求用户批准同一个主角设计。

### 第二优先：统一敌我、场景与反馈

- 敌兵、Boss 与友军共享同一画风，通过体型、色块和武器区分角色。Boss 可见身体或装备应合理覆盖真实可命中区，不能换回看不见的宽判定。
- 山道、树木、寨门、路障和 UI 配色围绕人物调整，保证人物、门值和危险预告清楚。避免背景细节与小人争抢注意力。
- 在现有事件上完善拉弓、放箭、受击、击破、增兵及晋升反馈，重点看手机尺寸下是否能感知。视觉事件不得额外结算伤害或改变射速。

## 下一批怎么验收

- 提供 360 和 390 宽的原尺寸截图与原速录像；大立绘和放大预览只作辅助。
- 展示 8/24/48 人在居中、贴左、贴右的状态，以及行走、射箭、增兵后的连续过程。注明正常玩法取得的人数和隔离排布测试，不能混称实玩。
- 把本轮实景与优化后实景并排，直接看角色是否清晰、主角是否突出、队伍是否拥挤、敌我是否统一。
- 最终仍由用户判断画面和动作观感；自动测试不能代替审美验收。

## 已通过的工程项与必须保留的边界

- 本轮已有 43 项测试通过、桌面浏览器连续首关 10/10 局完成；这些结果不代表美术通过。
- 保留山石损失提示、Boss 共享命中范围、地面预告层次、暂停后音效停止、队伍边缘修复，以及合并绘制带来的性能改善。
- 当前桌面十局平均帧率约 55.23–60 FPS，GPU 缓冲由 153.04 降至 49.53 MiB；正式士兵替换后要重新测量，不能沿用旧草模性能作为新版本结论，也不要直接堆 48 套复杂骨架。
- 不改首关默认人数、门值、伤害、节奏与胜负规则，不改存档键，不开放第二、第三关。平衡候选仍不合入默认配置。
- 微信只完成游客构建；开发者工具、微信真机及目标手机性能未通过验收。
