# 《一路长歌》前三局角色与美术试制说明

状态：候选方向，尚未选定；本文没有附带已生成的正式角色图。与`CODEX_FIRST_THREE_BRIEF.md`共同使用。先画少量能够作决定的图，再生产素材。

## 1. 这一轮首先让玩家认出谁

主角是一位刚开始带队的小人物。第一眼要看出年轻、利落、敢往前，暂不安排神秘身份和宏大使命。可先以年轻成年男性为样稿原型做比较，但最终性别、脸、名字均可换，不影响规则和关卡。

他在队首，体型略大于友兵，通过头部轮廓、肩线和前脚下的小中心标记被识别。不要依赖大量头顶文字。主角也计入真实兵力，1人时画面只剩他。

三关主角仍是同一个人。保留发型和主色；通过部件改变身份，不让每次升级都像换人。

|阶段|最少改变|姿态与奖励|制作顺序|
|---|---|---|---|
|布衣|束发、窄袖短衣、布腰带、简单护腕、弓|轻快前倾，有小人物的灵活|第一批完成战斗背/侧背和结算正面|
|头领|加短护身衣、小旗或旗号装饰|接住旗，站稳，队伍靠拢|随第一局胜利样板完成|
|统领|肩部和胸前加简化护甲，旗号完整|抬手示意队伍继续|第二局阶段才生产|
|城主|短披风、腰带和更完整护肩|城门前回望队伍|第三局结算需要，不做本轮未用的帝王战斗套装|

衣物、甲片、头饰为架空试制，不贴“某朝精准复原”标签。禁止在同一人物身上随机拼接明显冲突的帝王冠冕、戏曲盔头、外国中古重甲、枪械和仙侠法器。

友兵只做基础弓手一种。无需给每个士兵独立面孔、性别和职业树；用2–3处小变体和错相动作避免复制粘贴感。友军与敌军除颜色外，还应通过肩线、武器和队形区分。

## 2. 两个可比方向

### A：4.5头身国风动画战将（建议优先试）

体态有重量，头身比例略夸张，关节和武器清楚。面部简练，战斗背影以头巾/束发、肩线和腰带形成轮廓。用干净色块、少量笔触、柔和但明确的阴影建立体积，避免写实毛孔、满屏纸纹和AI插画的大面积发光。

底材可以温暖，但人物与环境不一起泛黄。候选主色为靛蓝配暖米白、少量铜赭；颜色可调整，识别逻辑保持。让敌兵的形状与武器先有差异，再用阵营色加强。

角色动作有小幅蓄力与释放，胜利不庄严说教。适合轻快征战感，允许一点人物表情，但不用每次晋升都搞笑。

风险：角色细节画得太多，缩小后仍旧看不清；动作只剩立绘抖动。先在实际小尺寸检查轮廓与手臂动作。

### B：3头身轻松小人物

头稍大、四肢短而有力，表情更鲜明；同一个人穿上新身份的衣服时有一点喜感。采用厚实简洁轮廓、较少内部线条和更鲜明的局部色，不做婴儿体态、无意义大腮红或橡皮人。

起手和收手更夸张，普通敌人败退可以带一点滑稽，Boss依然有体量与威胁。UI相应更圆润，但不用整屏大圆角卡片盖住场景。

风险：过于幼态、失去古代背景气质；战斗像玩具碰撞，力量感不足。要用落地影、清楚受击方向、武器速度和音效补足。

### 比较条件必须相同

每个方向只交：一张主角多视图草稿、一张第一局完整战斗构图、一张主角从布衣到头领的前后对照。战斗稿都使用同一组24可见人数、一个受阻门、一组敌兵和同一个Boss。再把主角/友兵缩到实际尺寸贴入8/24/48人的试排。

不能A交电影海报、B交界面截图；不能换场景、光照和兵力后把比较结果归结成画风。两套都标“未选定”，不一边叫默认一边擅自生产三关成品。

## 3. 构图与空间

逻辑设计画布720×1280。实际屏幕额外高度优先作背景延展和安全区，保持人物不变形与同样的可玩横向范围。最终适配需在360×800和390×844 CSS视口实测。

建议初稿布局：顶部安全区约8–10%放关名、进度和暂停；中上部留给Boss及下一组门；队首中心约在可玩画面70%处；底部约15%尽量留给手指。这里是可调的构图比例，不是把某个手机截图硬拉满的算法。

友兵候选显示尺寸42×56设计单位，主角约58×78，Boss约180–220高，随世界投影合理缩放。相较旧25×31纸兵，应明显提升主体存在感，但仍需以手机实机为准。

阵型建议最多6列，列距约28、行距22–25设计单位，用错列保留轮廓。最多48可见时约8行；不要为装下更多人把大家越缩越小。极左、极右采用表现层收拢，主角落点不偏离规则中心。不要让装饰队员跨出屏幕、站进永久UI或在角色脚下出现明显空白边。

场景分为远景、道路、中景边缘、少量前景经过物。山道→营寨→城门采用同一光向和透视，复用地面、树木、营旗、木料。不能把一张完整背景固定不动，再仅靠门下移表现前进。

道路必须让玩家看出可行宽度。可交互物的落地位置、预告范围和碰撞用同一套世界到屏幕投影。装饰遮挡从低处控制，不让树叶挡住即将结算的门数字。

## 4. 门的设计：它是游戏装置，不必伪造历史用途

采用有实体立柱和布幡的简化招兵入口。`+N`用单旗，`×2`用双旗或双层标牌，主数字形状不同。数学符号由引擎Label显示，不让生图生成正式文字和数字。

用很小的折线、布边或旗绳提供材质感。门脚必须落在真实通过平面上。当前所选门用边缘亮度/轮廓加强，正中归右。未来收益可作为调试或设计参考，不在首版增加每帧长算式提示。

受阻门上的木障横跨整半侧，并与其通行触发保持一致，不能画窄障碍却整侧扣兵。血条和“未清除：损失N”与门值分别有位置；击破后两者消失，门值不变。木屑不遮盖两扇门。

旗、立柱、数学符号都是游戏表现，不能拿它们作某朝代有招兵数字门的历史知识。

## 5. 敌人与Boss剪影

|对象|最重要的可辨形状|动作必须说清什么|
|---|---|---|
|普通敌兵|收束身形、短兵器、简单护具|受击后确实失去阵地；退场不生成第二次碰撞|
|弩手|明显的横向弩体、瞄准姿态|蓄力→已发射的区别；被打断与已发箭继续飞行可见|
|投矛头目|宽肩、背上短矛、举臂过肩|举臂锁定落点→出手→恢复|
|营寨弩将|更大的横向弩体、俯身瞄准|这次到底指向左、右还是中；每箭单独预告|
|守城主将|高而稳的轮廓、长弓、明确肩线|抬弓锁定与固定方向连箭的区别|

三个Boss可以共享部件动画方法，不能只把第一Boss换颜色。没有真实历史人物姓名，不借敌人形象影射某民族、阶层或现实政治角色。

## 6. 反馈最低集

|反馈|建议视觉时长/行为|不能破坏的事|
|---|---|---|
|增兵|数字立即更新；新兵约0.2–0.35秒从队伍两侧或后方合入；阵型扩张|不延迟规则生效、不暂停、不先加临时无敌|
|射击|小幅拉弓与释放；高兵力更密实的短箭迹|装饰箭不另计伤害、不射进邻道造成误导|
|命中|约0.06–0.1秒局部闪亮/后仰；清楚命中音|不每次震全屏，不全局停帧造成触摸卡顿|
|木障破坏|约0.2–0.4秒裂片、局部尘土|碎片无判定，不遮住门数字和下一次预告|
|受伤|显示一次-N，少量队员退场，短音与可关闭轻震|不多次扣同一事件，不用剧烈闪屏遮住危险|
|危险预告|纹理/边框/范围收束与武器动作同步|不只靠红色，不在落点锁定后暗中追踪玩家|
|Boss击败|后退、放下武器或退场，局部尘土|不自动跨过尚未耗尽的HP，不留下攻击任务|
|晋升|同一角色对照、旗号/护甲部件变化|解锁先保存，继续按钮不被长动画锁定|

受击与退场无血腥、断肢或尸体堆积。损兵表述为减员，败退用简洁动作表达即可。

首版普通视觉粒子池建议同时不超过80个，逻辑投射物与装饰池分开。这个是试制预算，不是已达到的性能结果。发现性能问题先减并发和独立材质，不先把主体缩回看不见。

## 7. 素材生产顺序与规格

第一批只服务第一局：布衣主角战斗与结算、头领结算部件、基础友兵、普通敌兵、投矛Boss、门/木障/山石、第一场景分层、HUD/按钮、必要反馈。第二批再加弩手、营寨Boss、营地部件与统领外观。第三批再加守城Boss、城门与城主结算。

每个角色先出正面/侧背/背向参考，锁定人物一致性；战斗不能拿正面微笑立绘朝上滑行。源素材可按主角高512、兵高256等规格制作，但运行显示尺寸由VisualConfig独立决定。多帧保持相同画布、脚底基准、光向、武器长度和身体比例。

透明素材必须有真实alpha；检查白边、伪透明棋盘格、手脚被裁切、阴影重复和画布留白。背景、人物、特效与UI分开输出。生产图中不画动态文字、不把士兵与数字门烘进背景。

记录资产ID、源文件、运行文件、作者/工具、许可、尺寸、角色方向、锚点、版本、用户确认状态。确认后的资产放到受保护目录，不再被旧`npm run art`覆盖。不要擅自下载商业角色、盗用素材、复制现成游戏的整屏UI或接入新付费服务。

若当前Codex有实际可用生图工具，可按以上要求出稿。若没有，交付完整素材请求清单和真实灰盒截图，说明缺失，继续独立工程工作；不能声称“已生成/已接入”。不要把代码拼出的几何图形包装成已达到本稿造型标准。

## 8. 用户的两次选择就足够推进

第一次看A/B：更愿意玩哪种角色气质；主角缩小后能否认出；布衣升级头领是否还是同一个人。

第二次亲玩正式第一局：移动是否跟手、增长是否明显、打击是否有反馈、Boss是否可读、自己是否愿意马上进入第二局。

其他非关键细节由执行者合理处理并记录，不要求用户逐个批准石头形状和每片屋瓦。角色方向未确认或第一关手感未过，不批量复制成三局正式成品。
