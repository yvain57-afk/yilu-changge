## 3. 同一轮完成的制作顺序

### 3.1 先把真实队伍整体换好

**主角的小屏版本。** 使用已认可主角作依据，保留身份识别元素与晋升关系。针对实际约 47–51 CSS px 的现有显示高度检查，减少衣纹、碎纹理和重复细线；强化头肩、躯干、腿部、持弓手和弓的轮廓。允许在现有可用空间内合理微调大小，不能靠无限放大造成遮挡。保留真实透明通道，检查浅底和深底下的白边、漏底及武器缺失。大立绘只作参考，不作为完成证据。

**一种正式普通友军。** 单独制作与主角同画风的普通弓手，造型比主角简洁，减少配件，用有限色块表达衣服、皮肤和武器；尺寸、肩背或衣饰应让主角一眼可辨。普通友军必须接入实际第一关。禁止将主角复制 48 次充当正式队伍，禁止只换队首而保留旧蓝色几何兵。

**队伍排布。** 调整行列间距、行间错位、绘制顺序及脚底阴影；保留小幅步态相位差，但不做大幅随机晃动和独立追赶。边缘处理不得再将多人压到同一坐标。表现阵型调整不移动真实队伍中心，不改变箭的逻辑通道、门判定和伤害规则。主角计入可见人数，最多 48 人；不能减少本应显示的人数来假装消除了拥挤。

在真实 Cocos 渲染路径中检查 8/24/48 人的居中、贴左、贴右与移动、射箭、增兵。先修正明显的碎线、拥挤、遮挡或比例不一致，然后继续下一项，不暂停等待用户重批主角。规则暂时无法自然取得的精确人数只在隔离排布夹具检查，标明“排布测试”，不得宣称正常玩法达成。

### 3.2 接着统一第一关敌兵和投矛 Boss

只做当前第一关实际出现的普通敌兵与投矛头目；不提前生产后续弩将、守城主将或整套兵种。

友军、敌兵与 Boss 使用一致的线条、材质和动作表达。敌我通过体型、色块、武器和姿态区分，不能只靠红蓝颜色。敌兵需要可识别的受击和退场，Boss 需要蓄力、出手、恢复、受击和败退的连贯动作。

Boss 的身体或合理装备应与当前共享命中区域相符。替换红色矩形调试护板，不能只删护板、保留看不见的宽判定；也不能为了素材方便擅自缩窄规则命中区。正式模式关闭青线和其他调试标记，调试模式保留可查证的命中区域。

### 3.3 再统一场景和界面

沿用当前认可角色的颜色关系与造型语言，完成第一关山道、少量近景树木、远处寨门、路障和数字门。中央道路保持干净，近中远层次清楚；无需增加几十种装饰。不要把一张带有人物、门和障碍的整屏生成图直接当成可玩背景。

角色、门值、木障状态和危险预告优先可读。数字和动态文案由引擎显示，不烘进插画。山石损失数值继续读取配置。受阻门的可见覆盖范围、实际覆盖范围和一次结算顺序保持一致。

首页、战斗、暂停和晋升结算使用同一套字体层级、面板与按钮语言。继续显示明确目标“从小人物起步，一步步当皇帝”，并如实注明本次仅开放第一关。把长工程说明移至评审材料，游戏内保留轻量的试制标识，不冒称最终版本。保留有效的异常提示和存储风险提示。

### 3.4 将关键反馈整合到这一关

利用已有实际事件同步拉弓、放箭、受击、击破、增兵和晋升。先完善已有接口，只有表现信息确实不足时才作小范围扩展，不借机推倒引擎结构。

- 8 → 20：真实兵力先结算；新友军快速并入，队形清楚展开，短音效与变化对应。
- 箭击：箭在真实目标上产生局部反应，不凭全屏晃动替代命中感。
- 击破：对象按规则退出，少量碎片或败退动作说明道路已经打开。
- Boss 投矛：蓄力、锁定、出手、落点与当前规则时间一致；危险清楚但不盖住队伍和门值。
- 晋升：进度先保存，同一主角接旗、展示护身衣变化；按钮无需等待长动画。

显示动画不得额外结算伤害、改变射速、门值、默认人数、移动规则或 Boss 时序。视觉箭不能制造相邻通道也被打中的假象。不增加操作延迟，不用拖慢游戏速度来强化重量感。
