## 本轮实际接入

- 主角小屏帧动画依据已认可的正面参考制作，保留发型、蓝围巾、浅衣、弓和晋升关系。战斗主角高 108 设计单位，360/390 宽分别约 54/58.5 CSS px；普通弓手高约 35/37.9 CSS px，造型独立、配件更少。
- 同屏最多 48 人包含唯一主角；普通友军使用共用图集的单 Sprite 帧动画，不给 48 人各装复杂骨架。八列、48 单位列距、31 单位行距与错位排布，整排贴边平移；保持真实中心，最低脚底仍在旧约束 −485 之上。原边界测试未放宽，仅将行分组从旧六列改为实际八列。
- 第一关敌兵使用持盾造型，有局部受击和短暂败退消隐；投矛 Boss 使用连续准备、蓄力、出手、恢复姿态。曲面木盾覆盖共享命中宽度，替换矩形调试护板；正常版关闭青线，调试入口仍可核对。
- 山道、远山、松树、寨门、山石、木障与数字门接入独立图集。数字与损失从引擎和配置显示，没有烘入插画；中央保留判断空间。
- 首页、战斗、暂停、设置、晋升结算统一墨青、浅纸色与金线边框。目标仍是「从小人物起步，一步步当皇帝」，明确只开放第一关。
- 增兵先真实结算，再用约 0.36 秒并入表现；射击使用既有 shot 事件，箭只沿真实通道绘制。命中火花、敌兵退场、木障碎片、Boss 投矛预告与落点均读取实际状态。胜利先保存，Boss 约 0.7 秒败退后展示同一主角换装接旗；结算按钮不等待晋升动画。

## 实际验证与限制

43 项测试通过，失败/跳过/TODO 均为 0；完整类型检查、核心类型检查及负向故障测试通过。Web 与微信游客构建均由 Cocos 3.8.8 完成，退出码 36。最终命令、起止时间与完整输出见 verification-run.json 及 check-*.txt。

浏览器实测：正常开始与触控通关、保存先于晋升展示、刷新保留进度、暂停/继续、取消触摸、原生切换标签页后的显式恢复、设置持久化、旧档保留、坏档/写入失败仍可游玩、每种视口五次重开、真实失败与旧手指抬起均通过。实际 WebAudio 暂停 RMS=0；恢复后重新有声。

完整录像 63.13 秒，390×844，H.264 + AAC 实际音轨；从首页到晋升，无剪接或速度变换。录制实际获胜 88 人，游戏内约 58.92 秒；片长还包含首页停留、Boss 败退和晋升观察。

完整回归：先运行 npm run build:web 和 npm run serve，再执行 node tools/verify-s2b.mjs。会依次执行规则、类型、负向、游客构建、排布、对照、音轨、流程、后台、音效、失败和十局测试。浏览器流程按顺序执行，避免相互抢前台。

构建期间发现旧导入缓存异常：一次构建返回成功码，却输出空主场景和引擎资源包，浏览器在 splash 材质启动时报错。已保留修改前 metadata 和缓存，重新导入后恢复；`tools/build.mjs` 现在额外检查 Web 主场景与引擎资源非空，避免只凭退出码宣称可玩。编辑器重新生成的 metadata 保留原 UUID。

微信仅游客身份构建；专用 AppID、微信开发者工具、微信真机、目标手机性能未验证。用户画风、队伍密度、动作和操作手感等待本轮集中试玩判断。
