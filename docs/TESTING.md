# 微信小游戏开发与验证

《一将成军》是唯一维护和发布的平台。手机验收在微信里进行，覆盖实际受影响的玩法、音频、存档或操作。

1. 按改动范围运行相关现有测试。修改 TypeScript 时运行 `npm run typecheck`。
2. 需要手机验证时，复用对应源码的微信构建。没有对应的构建时，使用下面的命令导出新目录。
3. 开发者工具先预览或走体验版，核对构建号，在手机微信里测试相关场景。记下机型、微信版本、游戏构建和结果。
4. 在微信后台分别核对送审和正式发布结果。线上版本号以「版本管理」为准。

```sh
npm run check:fast
npm run test:targeted -- tests/player-feedback.test.ts tests/music-shanhe.test.ts
npm run typecheck

# 示例版本号，实际填写本轮候选值。默认输出 build/wechat-0.12.15-2026111901。
npm run build:wechat -- --version 0.12.15 --build-number 2026111901
```

构建需要 Cocos Creator 3.8.8、项目 Node 依赖和 ffmpeg。构建命令使用《一将成军》的微信 AppID，按原始尺寸编码图集、保留正式战斗音乐和兵器音效，校验主包、资源和源码回执。它在 `.cache/wechat-build/` 记录构建和校验证据，拒绝覆盖旧目录。

常用手机短测从首页进入整备和战斗，按改动复测左右拖动、栅栏、开箱、结算、音乐切换、后台恢复或重新打开后的存档。大范围玩法或存档变更用 `npm run check:full`。浏览器可复用来定位共享画面的故障，真机流畅度、微信音频与首次分包加载以手机微信实测为准。

曾用于 iOS 名下的图集原稿、音频无损原稿、切图和玩法测试仍服务微信构建。发布包里的 WebP 和 MP3 不替代这些源素材。

## 微信包体基线

0.12.14 的微信上传回执记录主包 2,838,113 字节，总包 30,081,238 字节。项目按主包 4 MiB、总包 30 MiB 作本地校验，正式提审前用开发者工具复核。普通分包从总额度内分配。独立分包有单包上限。规则见 [微信小游戏分包加载](https://developers.weixin.qq.com/minigame/dev/guide/base-ability/subPackage/useSubPackage.html)。

当前打包时，资源进入 `resources` 普通分包，引擎仍在启动时预加载该分包。下一轮优化先拆分首页及前期对战需要的素材、后续场景和图鉴素材，再按玩家进入的页面和关卡加载。比较同一机型首次进入首页、首次开战和再次打开的耗时，同时检查画质和内存峰值。游戏美术源文件保留原尺寸。

## 当前回归结果

微信 0.12.14 基线从干净检出成功构建，资源分包中的 179 张图片及音频文件与已上传构建逐字节一致。全量 603 项通过 602 项。20 关参考走位模型都能通关，旧时长下限检查仍失败。此前 main 有 2 关低于下限，当前微信基线有 20 关低于下限。时长契约保持原值，后续调整需另用真机实测校准。
