## 3. 批次A：先修共享正确性，复用到所有页面

### R01：连续滚动与真实裁切（最高优先级）

已确认源码：FullMenu.ts:44只有整个卡片完全位于视口内才返回true。
影响：整备、人物详情、物品详情、奖励和结算；卡片稍越界就整块不绘制。单纯将比较符改成“相交”仍会把图像/文字画到固定栏，不能作为完整修复。

采用一个菜单专用的原生裁切内容层，固定页头/页签/底栏置于其外。优先用项目当前Cocos版本可用的原生矩形裁切组件；先核对本地引擎类型和坐标规则。
NativePaint基线没有公开通用clip API，不能虚构调用p.clip()，也不能仅裁九宫格背景而让Label、人物和Graphics越界。
裁切组件每个活动页面复用一套，不每卡一套，不嵌套多个滚动列表。

顺序固定：
1. 根据安全区、页头、底栏确定viewport。
2. 使用同一文本测量规则排版，计算真实contentHeight。
3. 在绘制前将scroll夹紧到[0,max(0,contentHeight-viewport.h)]。
4. 只剔除完全不相交的项；相交项正常提交，由viewport裁切。
5. HitRect也取与viewport的交集；裁外区域无事件。严重残缺的按钮暂不激活，不扩展热区穿过固定栏。
6. 拖动仍允许从部分可见卡片开始，达到阈值后本手势永久取消点击。
7. 长内容大于整个视口时仍可逐段看完，不能永久隐形。

菜单层可分为固定层、唯一裁切内容层、底栏层、弹窗层、安全错误层。可用菜单专用NativePaint实例协调这些层；不为此重写战斗引擎或路由架构。
裁切层的本地坐标、NativePaint屏幕坐标、UITransform坐标需有一次显式转换，避免重复减半屏或重复缩放。

验收：1px/8px/半卡/整卡/到底/回顶连续拖动；四尺寸；任一可见卡片不整块闪失，不漏字到页头，不误点出征，不在边界点击被裁掉的详情按钮。

### R04：新菜单的异常清理（源码风险，先注入复现）

基线FormalGame.drawMenu()调用menu.begin()和menu.end()，缺少覆盖整个菜单绘制的try/abort保护。此前战斗异常隔离不能自动覆盖新菜单。
对菜单图标/文字/裁切层分别注入失败，验证新风险；复現后关闭。没有复现也须检查各退出路径。

修复要求：
- 协调所有菜单绘制层：同一逻辑帧全部成功才commit；任何层失败都abort其活动节点及待发布热区。
- 不以finally调用end()提交半帧。
- 必要菜单图标缺失不能在FullMenu.figure/icon中静默return并维持可用状态；区分“未解锁剪影”和“实际资源错误”。
- 安全提示使用不依赖失效图集的已有安全层，暂停战斗逻辑与音源，保留存档，禁止递归调用同一失败绘制。
- 正常恢复、返回、连续开关页面后无旧节点/遮罩/触摸回调累积。
- 所有菜单新增层在onDestroy释放；abort不释放战斗仍在使用的共用图集。
